## 1. 公司画像:鼎安商业保险是谁

**鼎安商业保险股份有限公司 (DingAn Commercial Insurance)** 是一家虚构的国内中型 **商业财产 / 责任险 (Property & Casualty, P&C)** 公司,总部设在上海,业务覆盖华北、华东、华南、华西、华中五大区。它 **不做个人车险、不做寿险**,只服务 **企业客户**:工厂、写字楼、建筑工地、连锁餐饮、物流园、医院等。在真实市场里,它对标的是大型财险公司的商业线 (如平安产险商业线、人保财险、太平洋产险、中华联合)。

**业务规模 (对应本数据集):**

| 指标 | 规模 |
|------|------|
| 在保企业客户 | 1,000 家 (员工数 20 - 8,000 人的中小到中大型企业) |
| 保单总量 | ~3,100 张 (人均约 3 张,含有效 / 已到期 / 已注销) |
| 年化在保保费 | 约 5 - 10 亿元 (CNY) |
| 核保员 (Underwriter) | 40 人 (5 名经理 + 35 名核保员) |

## 2. 商业模式:鼎安怎么赚钱

保险公司的盈利公式比互联网公司朴素得多,但每一项都是大学问:

```
保险公司净利润 = 已赚保费 (Earned Premium)
              − 已发生赔款 (Incurred Losses)
              − 营业费用 (Expenses)
              + 投资收益 (Investment Income)
```

其中 **已赚保费 − 已发生赔款 − 营业费用** 这部分叫 **核保盈亏 (Underwriting Profit)**,是保险公司"主业"的成绩单。简化看,核保能不能赚钱只取决于两件事,而这两件事 **都是核保员 (Underwriter) 的职责**:

```
1. 保费收得对不对?   保费太低 → 赔不起 → 亏
                    保费太高 → 客户被对手抢走 → 没生意
2. 该不该接这单?     接了高风险客户 → 频繁出险 → 亏
                    拒绝了好客户   → 错失收入
```

**定价机制:** 鼎安按 **"基准保费 × 风险等级乘数"** 给企业报价。基准保费随险种和保额而定 (本数据集 3 - 80 万元区间),再乘以企业风险等级乘数 (低风险 0.8×、中风险 1.0×、高风险 1.4×、极高风险 1.9×),个别高风险大单可达约 150 万元/年。保险公司赚的是 **"收上来的保费" 减去 "赔出去的钱 + 运营成本"** 的差额——这个差额健康与否,完全由核保决策的质量决定。

**单位经济 (行业经验值):** 国内财产险公司的运营费用率 (Expense Ratio) 典型在保费的 25% - 30%。因此当赔付率 (Loss Ratio) 超过约 70%,加上费用就会突破 100% 盈亏平衡线 (详见第 9 节 Combined Ratio)。这就是为什么 70% 是核保员心里那条最重要的红线。

## 3. 行业普及:商业 P&C 保险这个市场怎么运作

如果你来自别的行业,这一节让你能和同事"聊上行"。

**这个行业创造什么价值?** 企业经营中随时可能发生意外——厂房失火、产品伤人、施工事故、营业中断、董事被诉。这些风险一旦发生,单靠企业自己可能赔到破产。商业保险把成千上万家企业的风险 **汇集 (pooling) 起来**:大家平时交保费,少数倒霉的出险时由这个资金池赔付。保险公司的本事,就是 **准确地给每家企业的风险定价**,既不让好客户多掏钱,也不让坏风险占便宜。

**主要玩家类别 (不点真实公司名):**

- **保险公司 (Carrier/Insurer):** 承担风险、收保费、付赔款的主体,如本数据集的鼎安。
- **保险经纪人 (Broker):** 代表 **投保企业** 在多家保险公司之间比价、拿条款、递交申请的中介。商业保险 80%+ 的业务通过 broker 进来。
- **公估 / 理赔调查方 (Adjuster / Loss Assessor):** 出险后做现场定损的专业方,可能是保险公司内部的,也可能是第三方公估机构。
- **再保险公司 (Reinsurer):** 保险公司把超大保单的部分风险再转卖出去的"保险公司的保险公司"(本数据集未建模再保险)。
- **评级 / 征信机构:** 给企业财务健康度打分的第三方 (如中诚信国际、大公国际)。

**监管与合规框架 (国内):** 商业财险受 **国家金融监督管理总局** 监管 (保险条款、偿付能力、市场行为)。企业客户自身则受多部门监管,这些处罚记录是核保的重要外部信号:**应急管理部** (安全生产)、**生态环境部** (环保)、**国家市场监督管理总局** (产品质量)、**国家消防救援局** (消防)、**国家税务总局**、**人力资源社会保障部** (劳动用工) 等。

**当下塑造行业的宏观力量:**

1. **承保利润承压:** 行业 Combined Ratio 普遍在 97% - 102% 之间,核保业务薄利甚至微亏,利润越来越依赖投资收益和精细化风控。
2. **数据与 AI 化:** 续保核保是高度重复的取数 + 判断工作,正被 Text2SQL、RAG、决策合成等 AI Agent 改造——这正是本数据集存在的理由。
3. **风险结构变化:** 气候巨灾、网络安全、董事责任等新型风险上升,传统按历史经验定价的方式越来越不够用。

## 4. 项目框架:你是谁、要交付什么

**你的角色:** 你是鼎安的 **承保运营分析师 (Underwriting Operations Analyst) 实习生**,直接汇报给 **核保经理 (Chief Underwriter / Underwriting Manager)**。你的日常工作有三类:

1. **续保季的批量数据准备。** 每年 6 月、12 月是大批量续保高峰,核保员要在 30 天内决策几百张保单是否续保、保费上下调多少。他们会让你"把这家企业过去 3 年的赔付情况拉一下,跟行业平均比一比"——你写 SQL。
2. **个案深度调查的取数。** 当某张保单理赔金额异常,或某条理赔通讯里出现"律师函"这类关键词,核保员要你"把这家公司近 2 年所有理赔细节、付款行为、监管记录一起调出来"。
3. **辅助构建 InsightUnderwriter AI Agent。** 公司在做 AI 转型,要让 AI Agent 自动完成上述两类工作的初稿。你的工作是给 AI 喂料、写 prompt、对比 AI 输出与人工输出的差异。

**你要交付什么:** SQL 查询结果、续保分析底稿、以及给 AI Agent 用的训练 / 验证数据。最终交付对象是核保经理、承保副总,部分汇总指标上到 CFO / CRO 的季度风险评审。

**InsightUnderwriter AI Agent 是项目的北极星。** 目标是构建一个扮演核保员角色的 AI Agent,在 5 分钟内输出一份续保推荐书初稿。它由 4 个子 Agent 串成流水线:

| 子 Agent | 职责 | 主要数据来源 |
|----------|------|--------------|
| **Text2SQL Agent** | 查公司档案、3 年财务趋势、历史保单+理赔、付款行为、未整改隐患 | 全部 24 张表 |
| **RAG Agent** | 从理赔通讯里检索欺诈 / 争议 / 律师介入信号,从现场检查里检索隐患 | `claim_communication`、`site_inspection` |
| **External Data Agent** | 查监管处罚、第三方信用评级、行业基准 | `regulatory_filing`、`third_party_report`、`industry_benchmark` |
| **Decision Synthesis Agent** | 综合上述输入,给出 续保 / 有条件续保 / 拒保 推荐 + 保费变化幅度 + 关键风险点 | 上述全部输出 |

> **重要边界:** AI Agent 只产出 **初稿**。最终拍板的责任永远在人类核保员身上 (这也是监管要求)。本数据集是这个 AI Agent 的冷启动训练料 + 业务逻辑验证集。

**本数据集刻意不覆盖的部分** (诚实声明,出于复杂度控制):个人级数据保护合规 (PII 脱敏)、再保险合约与分保、精算定价模型本身、跨保险公司的征信共享平台。

## 5. 要回答的业务问题

整个数据集——表结构、数据分布、SQL 查询——都是为了回答下面这几个具体问题。SQL 文档里的每一条查询都能追溯到其中之一。

1. **风险定价对不对?** 核保员给保单打的风险评分 (risk_score)、给企业定的风险等级 (risk_tier),与这些保单 / 企业后续真实的赔付率是否吻合?如果打高分的反而不赔、打低分的反而频繁出险,定价模型就失效了。(对应查询 B11、B30、B35)
2. **哪些客户该涨价、该拒保、该留住?** 用 3 年累计赔付率 (Loss Ratio)、行业基准偏离度、财务恶化信号,把客户分成"优质留客 / 涨价 / 有条件续保 / 拒保"四类。(对应 D2、D10、D11、B5、B13、B34)
3. **续保决策做得准不准?** 当年被"续保 + 涨价"或"拒保"的客户,后续赔付率是否真的如预期变化?用来复盘和校准决策模型。(对应 B10、B20、B32)
4. **理赔里有没有欺诈 / 争议 / 失控信号?** 从非结构化的理赔通讯里识别 fraud_signal、attorney_involvement、dispute_escalation,从准备金 (reserve) 反复上调里识别失控案件。(对应 D5、D9、B16、B17、B21、B22)
5. **客户的付款行为和外部风险信号说明了什么?** 付款逾期、监管处罚、信用评级下调,这些是否能作为续保风险的早期预警?(对应 D7、D12、D13、B27、B29、B31)

## 7. 行业知识科普 (Underwriting 101)

在看任何表之前,先把这 5 个最基础的概念吃透。能把它们复述给别人听,后面的数据基本可以秒懂。

### 7.1 什么是 Underwriter (核保员)

**用人话讲:** 核保员就是 **"决定是否承保、以什么价格承保"** 的那个人。类比:你去银行办信用卡,后台有人审你的征信、决定给不给卡、给多大额度——那是个人金融的核保员。商业保险的核保员干同一件事,只不过对象是企业、金额是上百万的保单、依据是几十个数据维度的综合判断。一个核保员每月处理 50 - 100 张保单,资深的能到 150 张。AI Agent 的目标是把每张保单的初步分析从 30 分钟压缩到 3 分钟。

### 7.2 什么是 Broker (保险经纪人)

**用人话讲:** Broker 代表 **客户 (投保企业)**,在多家保险公司之间比价、拿条款、递交申请。商业保险 80%+ 的业务通过 broker 进来,不是企业直接找保险公司。原因:大企业的保险需求复杂 (财产 + 责任 + 雇主 + 董事 + 营业中断一堆险种),broker 跟所有大保险公司都熟、能挑最优,且 broker 的佣金由保险公司付 (5% - 20%),对客户"免费"。

对核保员而言,broker 是 **流量来源**,也是 **风险过滤的第一道关**:好 broker 不送烂单,烂 broker 会塞"急救型"投保 (企业刚出过事故急着找下家)。因此鼎安给 broker 评级:战略合作 / 重要合作 / 一般合作 (`broker.tier`)。

### 7.3 Underwriter vs Claim Adjuster (核保员 vs 理赔员)

新人最常混淆这两个角色,它们是 **完全不同的两类岗位**:

| 维度 | Underwriter (核保员) | Claim Adjuster (理赔员 / 公估师) |
|------|---------------------|----------------------------------|
| 工作时点 | 保单 **承保前 + 续保前** | 保单 **出险后** |
| 核心问题 | "这单要不要做?什么价格做?" | "事故是真的吗?该赔多少钱?" |
| 主要产出 | 核保意见书 + 报价单 | 定损报告 + 赔款核算 |
| 数据来源 | 财务报表、行业基准、信用报告、历史赔付 | 现场勘查、目击笔录、维修发票、医疗记录 |
| 在数据集中 | `underwriter` 表 | `claim_adjuster` 表 |

### 7.4 商业保单的生命周期

一张商业保单不是签完就结束——它在 365 天里持续产生数据,而这些过程数据才是续保决策时最有价值的信息:

```
T−30 天  投保申请 (broker 提交) → 核保评估 → 报价 → 客户接受 → 签发 (bind)
T−0  天  保单生效 (effective_date)
         同步产生: policy_coverage (承保项目)、policy_premium_history (初承记录)、
                   invoice (4 期季缴账单)、可能的 site_inspection (现场检查)
T 中间   出险 → 理赔: claim 立案 → claim_event 状态推进 → claim_communication (RAG 主源)
                     → claim_reserve 准备金调整 → 最终赔付
T 中间   保单批改 (endorsement): 扩展承保 / 改地址 / 增减除外责任 → 同步写 policy_premium_history
T+365 天 保单到期 → 核保员复盘 → renewal_decision (续保 / 有条件续保 / 拒保)
```

### 7.5 续保 (Renewal):核保员最重要的工作

**为什么续保比新单重要?** 新单信息有限 (只有 broker 提供的资料),大部分靠行业经验;续保信息充分 (一整年真实赔付数据 + 通讯记录),可以做精细化定价。续保决策有 3 种结果:

| 决策 | 占比 | 典型触发条件 | 对客户的含义 |
|------|------|--------------|--------------|
| **续保** (Renewed) | ~65% | 赔付率 < 70%、财务稳健、无大额未结理赔 | 保费小幅调整 (±10%) |
| **有条件续保** (Conditional) | ~25% | 赔付率 70% - 90%、有可整改隐患 | 必须做出改变 (完成整改 / 提高免赔额 / 加限制条款) 才能续 |
| **拒保** (Declined) | ~10% | 赔付率 > 100%、多次诉讼、监管重罚、财务恶化 | 客户必须找下家承保 |

## 8. 术语表 (Glossary)

行业的"普通话"。每个术语给出 **英文术语 + 中文大白话解释 + 在本数据集里为什么重要**。第一次看不懂没关系,但这些词你要能张口就来。

### 8.1 角色与渠道

| 术语 | 大白话 | 为什么重要 |
|------|--------|------------|
| **Underwriter** (核保员) | 决定要不要承保、定多少保费的人 | 公司赚不赚钱本质看核保决策质量;关联 policy / renewal_decision / risk_assessment |
| **Broker** (保险经纪人) | 代表客户找保险公司、比价递单的中介 | 80%+ 业务的来源;tier 评级影响业务分配 |
| **Claim Adjuster** (理赔员 / 公估师) | 出险后做现场定损、核算赔款的人 | 决定实际赔多少;关联 claim / claim_communication |
| **Carrier / Insurer** (保险公司) | 承担风险、收保费付赔款的主体 | 本数据集即鼎安自身 |

### 8.2 保单与承保

| 术语 | 大白话 | 为什么重要 |
|------|--------|------------|
| **Policy** (保单) | 一份为期 1 年的保险合同 | 核心营收实体;`policy` 表 |
| **Premium** (保费) | 客户每年付给保险公司的钱 | 收入来源;`current_annual_premium_cny` |
| **Coverage Limit** (保额) | 最多赔多少 | 风险敞口上限 |
| **Deductible** (免赔额) | 出险时客户自己先扛多少,超出才赔 | 高免赔=保费便宜+少报小案;续保谈判筹码 |
| **Premium Rate** (费率) | 年保费 ÷ 保额 × 1000,单位保额的售价 | 跨保单比较定价是否合理 |
| **Endorsement** (批改) | 保单中途的修改 (改地址 / 增减承保) | 频繁批改=初承评估不准,是风险信号 |
| **Renewal** (续保) | 保单到期时决定是否继续承保 | 核保员最重要的工作 |
| **Bind** (签发 / 出单) | 核保通过后正式生成保单 | `bound_at` 早于 effective_date 7-30 天 |

### 8.3 理赔与赔付

| 术语 | 大白话 | 为什么重要 |
|------|--------|------------|
| **Claim** (理赔 / 报案) | 客户出险后向保险公司索赔 | `claim` 表;一张保单 0-4 个理赔 |
| **Loss Amount** (申报损失) | 客户报案时声称的损失 | `loss_amount_cny`,可能虚高 |
| **Paid Amount** (已赔金额) | 定损调查后实际赔出去的钱 | `paid_amount_cny`,典型为申报的 60%-98% |
| **Reserve** (准备金) | 对未赔完的开放理赔,财务上预提的"待付钱" | 反复上调=事态恶化的最强信号;`claim_reserve` |
| **Claim Frequency** (出险频度) | 理赔件数 ÷ 保单数 | 频度高=管理有问题 (人为风险) |
| **Severity** (案均损失) | 平均单笔损失金额 | 衡量风险的"烈度" |
| **Reporting Lag** (报案延迟) | 报案日 − 出险日的天数 | > 7 天有道德风险 (可能凑证据) |

### 8.4 风险与外部信号

| 术语 | 大白话 | 为什么重要 |
|------|--------|------------|
| **Risk Tier** (风险等级) | 公司层面的粗分类:低/中/高/极高 | 影响保费基础乘数;`company.risk_tier` |
| **Risk Score** (风险评分) | 保单层面 0-100 的精细评分,越高越危险 | 核保员打分;`risk_assessment.risk_score` |
| **Credit Rating** (信用评级) | 第三方评的财务健康度 (AAA ~ CCC) | 连续下调=财务恶化;`third_party_report` |
| **Debt-to-Equity Ratio** (负债权益比 / 产权比率) | 负债 ÷ 净资产,> 1 警戒、> 2 红线 | 财务紧张信号。注:此字段是"负债/净资产",非"负债/总资产" |
| **Loss Run** (赔付率汇总单) | 按 公司 × 承保年度 × 险种 汇总的赔付率台账 | 续保决策最高频查的表;`loss_run` |
| **Industry Benchmark** (行业基准) | 行业平均赔付率 / 频度 / 保费区间 | 单家赔付率必须对标行业才有意义 |
| **Subcontractor** (分包商) | 总承包商雇用的专业施工方 | 分包商事故由总包保单承担,是建工险风险信号 |

### 8.5 RAG 信号标签 (理赔通讯分类)

`claim_communication.signal_tag` 是为 RAG Agent 准备的标注数据,共 6 类:

| 标签 | 大白话 | 为什么重要 |
|------|--------|------------|
| **normal_cooperative** | 正常合作,无异常 | 负样本基线 (~40%) |
| **investigation_note** | 调查取证过程笔记 | 标记调查活动 (~20%) |
| **fraud_signal** | 欺诈风险信号 | RAG 核心训练目标 (~12%) |
| **dispute_escalation** | 争议升级 | 争议预警 (~12%) |
| **settlement_negotiation** | 和解谈判过程 | 跟踪和解 (~10%) |
| **attorney_involvement** | 律师介入 | 高风险,常意味诉讼 (~6%) |

## 9. 关键指标与公式

下面是 SQL 查询里会用到、或读者应当知道的所有核心指标。公式用 SQL 风格的伪代码表达,并标注口径约定 (口径不统一会导致下游 SQL 互相打架)。

### 9.1 赔付与盈利核心

**Loss Ratio (赔付率)** —— 整个行业最核心的 KPI:

```
Loss Ratio = 赔款总额 (Paid / Incurred Losses) / 保费总额 (Premium)
```

口径约定:本数据集统一采用 **已付赔款 (paid)** 口径 (`SUM(claim.paid_amount_cny) / SUM(policy.current_annual_premium_cny)`),已拒赔 / 在办理赔的已付为 0。`loss_run` 表已按此口径预聚合。分档解读:

| Loss Ratio | 含义 | 核保员反应 |
|-----------|------|-----------|
| < 50% | 极好客户 | 续保 + 可考虑降价 |
| 50% - 70% | 优质客户 | 续保,小幅调整 |
| 70% - 90% | 临界区,亏钱边缘 | 续保 + 涨价 10%-25% + 加条件 |
| 90% - 110% | 已经亏钱 | 有条件续保 + 大幅涨价 30%+ |
| > 110% | 严重亏损 | 拒保 (除非战略客户) |

**Combined Ratio (综合成本率)** —— 核保主业到底赚不赚钱:

```
Combined Ratio = Loss Ratio + Expense Ratio
                 (赔付率)     (费用率, 典型 25%-30%)
```

> Combined Ratio > 100% = 单看核保业务在亏钱 (靠投资收益兜底);< 100% = 核保业务本身赚钱 = 健康保险公司。国内财险普遍在 97% - 102%。这就是 70% 赔付率是分水岭的根本原因:70% 赔付 + 30% 费用 = 100% 刚好保本。

### 9.2 客户与财务

```
客户在保保费总额 = SUM(policy.current_annual_premium_cny WHERE status='有效')
客户累计赔付总额 = SUM(claim.paid_amount_cny  经由 policy.company_id 关联)
负债权益比       = total_liabilities_cny / (total_assets_cny − total_liabilities_cny)
净利润率         = net_profit_cny / revenue_cny
3 年累计赔付率   = SUM(loss_run.total_losses_cny) / SUM(loss_run.total_premium_cny)  WHERE year >= 起始年
行业基准偏离度   = loss_run.loss_ratio − industry_benchmark.avg_loss_ratio   (同行业同年度)
```

### 9.3 承保运营

```
续保率            = COUNT(decision='续保') / COUNT(*)                     来源 renewal_decision
拒保率            = COUNT(decision='拒保') / COUNT(*)                     来源 renewal_decision
平均续保保费变化  = AVG(premium_change_pct WHERE decision IN ('续保','有条件续保'))
保费滑动 (次数)   = COUNT(policy_premium_history WHERE change_event_type='批改') PER policy_id
配额完成率        = COUNT(当月签发保单) / underwriter.monthly_quota_policies
```

> **Claim Frequency 的两种口径 (务必区分):** `industry_benchmark.avg_claim_frequency` 是 **比率** (件数 / 保单数),用于对标;而 `loss_run.claim_frequency` 是 **绝对件数 (计数)**。两者单位不同,不可直接相减或比较。

### 9.4 理赔与时效

```
案均损失 (Severity) = AVG(claim.loss_amount_cny)
赔付比例            = paid_amount_cny / loss_amount_cny    (定损核减程度)
平均结案天数        = AVG( MAX(claim_event.event_date WHERE type='结案归档') − claim.reported_date )
开案 (在办) 件数    = COUNT(claim WHERE status IN ('已立案','调查中','定损中'))
报案延迟            = reported_date − incident_date    (> 7 天有道德风险)
准备金增长倍数      = latest_reserve / initial_reserve   (> 1.5 危险, > 3 失控)
```

> 口径约定:"开案 / 在办"统一定义为 status ∈ {已立案, 调查中, 定损中};"已支付"≈待结案、"已结案 / 已拒赔"已闭环,均不计入在办 (D5 / D15 / B18 一致)。

### 9.5 付款与外部风险

```
准时付款率    = COUNT(payment WHERE days_late <= 0) / COUNT(*)
平均逾期天数  = AVG(payment.days_late WHERE days_late > 0)
应收账款总额  = SUM(invoice.amount_due_cny WHERE status IN ('待支付','逾期'))
监管处罚次数  = COUNT(regulatory_filing WHERE filing_date >= REFERENCE_DATE − N 年)
评级下调次数  = COUNT(third_party_report WHERE rating_change='下调')
欺诈信号率    = COUNT(claim_communication WHERE signal_tag='fraud_signal') / COUNT(*)
隐患整改率    = COUNT(site_inspection WHERE remediation_status='已完成') / COUNT(hazards_identified IS NOT NULL)
```
