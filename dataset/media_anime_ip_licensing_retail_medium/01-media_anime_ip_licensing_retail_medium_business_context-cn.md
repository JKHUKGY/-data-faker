## 1. 公司画像

**Ember & Ash Licensing Group** 是一家总部位于加州 El Segundo 的虚构北美娱乐 IP 授权代理公司,2016 年成立。它不生产任何产品,也不拥有任何动画版权——它的生意是"中间人":代表动画版权方,在北美市场把动画 IP 授权给愿意生产周边商品的制造商 (被授权商, licensee),再从这些制造商的批发销售额里抽成。

公司画像(数量级,非精确值):

- **员工:** 约 45 人,含一支授权经理团队 (licensing manager,负责被授权商关系与合同谈判)、一支零售渠道分析团队、一支版税稽核团队、法务和财务。
- **收入:** 公司全品类(不止动画,还包括少量其他娱乐 IP)、全历史存量合同,从被授权商处**收到的毛版税流水**约 6000 万美元数量级——这是毛流水而非净收入,其中大部分会按母授权协议分给动画版权方(见第 6 节),Ember & Ash 自留的佣金收入规模远小于这个数字。
- **本数据集的范围:** 聚焦公司**动画品类**里最近约 22 个月内活跃的一个分析切片——24 部动画 IP、32 家被授权商、117 份授权合同。这不是公司全部品类、全部历史合同的总账,而是用来支撑动画品类续约、稽核、渠道合规决策的一份有代表性的样本(详见第 6 节"数据范围")。
- **地域:** 被授权商总部分布在美国和加拿大主要城市(Los Angeles、New York、Chicago、Toronto、Vancouver、Denver 等),销售的零售终端覆盖美加两国。

## 2. 商业模式

Ember & Ash 的赚钱方式是**版税代理 (royalty licensing agency)**:它不生产、不囤货、不直接面对消费者,而是靠"授权 + 抽成"赚钱。

流程是这样的:

1. Ember & Ash 与被授权商 (licensee,通常是玩具、服饰、收藏卡牌等品类的北美制造/分销企业) 签订**授权合同 (license agreement)**,把某部动画 IP 在特定品类、特定零售渠道、特定地域范围内的商品化权利授予对方,期限通常 12 到 36 个月。
2. 被授权商按合同约定的**版税率 (royalty rate,批发净销售额的 7% 到 12% 左右)**,把商品卖给零售商赚到的批发收入按比例分给 Ember & Ash。(这个 7%-12% 是**品类基准**区间;单份合同的实际费率会因谈判在基准上下浮动,所以全库实际费率落在约 5.5%-13.5% 之间。)
3. 大多数合同还带一个**保底金额 (minimum guarantee, MG)**——不管被授权商卖得好不好,合同期内至少要付这么多版税,这是 Ember & Ash 对下行风险的保护。(这里说的是**整个合同期的总下限**;要判断某个时点"进度跟没跟上",不能直接拿累计版税跟这个总额比,得先按已经过去的合同时间比例折算——具体口径见第 7、9 节的 MG proration。)
4. 被授权商每个"合同季度"(从合同起始日起每 91 天一期,不是自然日历季度)自己上报净销售额和应付版税,Ember & Ash 收钱、按约定比例再分给动画版权方。

单位经济(unit economics)层面:一件衍生品从制造商批发给零售商的价格,遵循消费品行业惯例的 **"keystone" 加价法则**——批发价约为建议零售价 (MSRP) 的 50%。版税只对**批发净销售额**抽成,不对零售终端消费者实际付的价格抽成——这个"批发 vs 零售"的口径差异,是理解本数据集所有金额字段的第一道关卡。

所以这家公司的利润最终取决于三件事:

1. **选对 IP、选对品类**——押注在会火的动画上,续签会持续动销的组合,砍掉不动销的组合。
2. **版税收得对不对**——被授权商是不是老实上报了真实销售额。
3. **被授权商有没有越界**——是不是在合同没授权的渠道里偷偷铺货。

## 3. 行业普及:北美娱乐 IP 消费品授权

如果你来自别的行业,这一节让你快速看懂这门生意。

**这个行业创造什么价值。** 动画、电影、游戏等娱乐 IP 拥有庞大的粉丝群体,但版权方自己通常不擅长、也不想直接下场生产玩具、服装这类实体商品——那需要完全不同的供应链、模具工厂、零售渠道关系。**授权代理商 (licensing agent)** 填补了这个中间地带:它一头懂 IP 和粉丝文化,另一头懂消费品制造和零售分销,把两边撮合起来,同时负责合同谈判、品牌调性把关、以及最容易被忽视但同样重要的一环——**版税稽核**。

**主要玩家类别(不点名真实公司)。**

- **版权方 (IP owner / licensor):** 动画制作方或其北美发行权持有者,拥有 IP 但通常不直接管理数十家制造商的合同细节。
- **授权代理商 (licensing agent):** 像 Ember & Ash 这样的中间商,代表版权方管理被授权商组合,赚取版税分成。
- **被授权商 (licensee):** 实际生产商品的制造/分销企业,按品类专精(玩具、服饰、收藏卡牌、家居用品等)。
- **零售商 (retailer):** 大盒子连锁 (big box)、专卖店、电商平台等,从被授权商那里批发商品再卖给消费者。

**监管与合规框架(北美)。** 消费品授权不像金融、医疗那样有专门的联邦监管机构,但仍受几类通用框架约束:

- **CPSC(Consumer Product Safety Commission,美国消费品安全委员会):** 玩具、儿童用品的安全标准,尤其影响面向 kids 受众的 SKU。
- **商标与版权法:** 授权合同本质是许可使用受版权/商标保护的 IP 素材,越权使用属于侵权。
- **各州消费者保护法与加拿大对应法规:** 广告宣传、产品标签的合规底线。
- **合同法下的审计权 (audit rights):** 几乎所有授权合同都会写明代理商有权对被授权商的销售记录进行稽核——这是本数据集"版税稽核"这条业务线存在的合同基础。

**当下的宏观力量。** 北美动画观众群体在过去几年快速扩大,带动衍生品市场规模上升;与此同时,电商渠道让"灰色转售"和"越权铺货"变得更难追踪(零售商自己也未必知道货是从哪条供应链流出的);被授权商上报制度本质上是"自证清白",天然存在低报动机,这让版税稽核成为授权代理商越来越重视的职能。

## 5. 本项目要解决的业务问题

整个数据集是为回答下面五个核心业务问题而设计的。每个问题都在 ER 文档里有对应的数据陷阱或数据信号,并在 SQL 查询文档里有对应的查询。

1. **Q1 内容动销与续约优先级 (Sell-Through & Renewal Priority):** 哪些"IP x 品类"组合的零售动销 (sell-through) 表现最好,值得优先续签更长期限或更大范围的授权?哪些组合动销持续低迷,该在到期后砍掉?
2. **Q2 版税稽核与低报风险 (Royalty Audit & Underreporting Risk):** 被授权商自报的版税收入,和用零售终端 POS 数据反推出的实际版税相比,差多少?哪些被授权商系统性地低报?
3. **Q3 热度-动销滞后 (Popularity-to-Sell-Through Lag):** 一部动画在流媒体端的热度峰值(比如新一季首播),要过多久才会体现为零售端衍生品销量的明显上升?这个滞后期对补货计划意味着什么?
4. **Q4 越权铺货合规 (Unauthorized Channel Compliance):** 有没有被授权商在授权合同没有覆盖的零售渠道里卖货?这部分收入有没有被误算进"合规收入"里,污染了业绩评估?
5. **Q5 保底金额达成追踪 (Minimum Guarantee Pacing):** 哪些活跃合同的版税累计进度,落后于按时间进度折算的保底金额 (minimum guarantee) 目标,需要在续约谈判前重新评估?

除了这五个 marquee 问题,数据集还支持一批运营类分析:被授权商组合健康度、渠道授权覆盖率、授权经理的合同组合负荷、品类版税率对比等,用来回答日常运营和组合管理的问题。

## 7. 行业知识科普

外行看懂这份数据前,需要的大约半小时背景。建议按"一份授权合同的一生"来理解。

**1) 授权合同的六个阶段。**

```
签约 (signed) → 合同生效 (contract start) → 产品开发上市 (SKU launch)
   → 零售动销 (POS sell-through) → 按季自报版税 (royalty report) → 稽核 (audit)
```

- **签约:** Ember & Ash 和被授权商就 IP、品类、渠道范围、地域范围、版税率、保底金额谈妥,签下合同。
- **合同生效:** 合同起始日通常在签约后 1-2 个月,给双方留出法务和物流准备时间。
- **产品开发上市:** 被授权商设计、打样、生产,一款 SKU 从合同生效到真正在货架上销售,通常还要再等 2-4 个月。
- **零售动销:** 商品在授权范围内的零售渠道逐周销售,产生 POS (point of sale,零售终端销售) 记录。
- **按季自报版税:** 每个"合同季度"(91 天一期,从合同起始日起算,不是自然日历季度)结束后 15-45 天内,被授权商自己核算净销售额并申报应付版税。
- **稽核:** Ember & Ash 用独立的零售数据(POS)反推"真实"应付版税,和被授权商的自报数字比对,揪出差异。

**2) 版税率与保底金额。** 版税率 (royalty rate) 是被授权商批发净销售额里要分给 Ember & Ash 的比例,不同品类的行业惯例不同(收藏卡牌、玩具等品类因为复购率高、单价适中,版税率通常在 10%-12%;家居用品、文具等品类竞争激烈、利润薄,版税率通常只有 7%-9%)。要注意这两个区间是**品类基准**,每份合同的实际费率会在基准上下约 ±1.5pp 浮动,所以全库实际费率落在约 5.5%-13.5% 之间——分析真实合同的费率时不要拿基准值去硬套。**保底金额 (minimum guarantee, MG)** 是合同期内被授权商无论卖得好坏都必须支付的版税下限——本质上是 Ember & Ash 对"这个 IP 会不会不好卖"这个风险的对冲。保底金额通常按合同起始日到当前的时间比例做**分期折算 (proration)**:合同已经过去多少比例的时间,就该累计付到保底金额的多少比例。

**3) 批发 vs 零售、"keystone" 加价。** **批发价约等于建议零售价 (MSRP) 的 50%**,业内俗称 "keystone" markup。版税只对批发净销售额抽成,理解这一点很重要——不要把 MSRP 当成版税计算的基数。

**4) 授权范围的三个维度。** 一份授权合同同时限定三件事:**品类范围**(只能做玩具,不能做服饰)、**渠道范围**(只能进大盒子连锁和专卖店,不能进电商)、**地域范围**(只能在美国卖,还是美加两国都能卖)。这三个维度共同构成"合规销售"的边界——任何一个维度越界,都是"越权铺货"。

**5) POS 与 sell-through rate。** POS (point of sale) 数据是零售终端的实际销售记录,和"被授权商出货给零售商"是两回事——被授权商出的货可能堆在零售商仓库里卖不动。**Sell-through rate**(动销率)衡量的是"货到了货架之后,卖出去的速度",是判断一个 IP x 品类组合真正受不受欢迎的关键指标,比"出货量"更能反映真实市场需求。

**6) 流媒体热度指数与零售滞后。** 一部动画在流媒体上"热"起来(比如新一季首播带来的搜索量、观看时长暴涨),不会立刻反映在零售货架上——零售商需要看到热度信号后追加订货,供应链走完补货流程,通常要**滞后几周**才能体现为实际销量上升。理解这个滞后期,决定了 Ember & Ash 该不该在一部动画刚开始"热"起来的时候就提前催被授权商备货。

**7) 自报制度与稽核。** 被授权商的版税申报本质上是"自证清白"——他们既是卖货的人,也是算钱、报数字的人,这天然存在低报动机(少报销售额 = 少交版税)。稽核的价值就在于用一份被授权商无法操纵的独立数据源(零售终端 POS)去反推"应该"交多少版税,揪出自报数字和真实数字之间的缺口。

| Territory | 地域范围(美国/加拿大/美加两国) | 授权范围三维度之一 |
| Product category | 品类(玩具、服饰、卡牌等) | 授权范围三维度之一,也是版税率差异的来源 |
| Retail channel | 零售渠道(大盒子连锁/专卖店/电商等) | 授权范围三维度之一,Q4 越权铺货的核心维度 |
| Channel authorization | 渠道授权,即合同允许在哪些渠道销售 | Q4 判断是否越权的依据 |
| MSRP | 建议零售价 (Manufacturer's Suggested Retail Price) | 不是版税计算基数,容易被新手用错 |
| Wholesale price | 批发价,制造商卖给零售商的价格 | 版税计算的真正基数 |
| Keystone markup | 批发-零售"对半"加价惯例(批发价≈MSRP的50%) | 解释 wholesale_price_usd 的取值逻辑 |
| Net wholesale sales | 批发净销售额 | 版税率的计算基数 |
| POS (Point of Sale) | 零售终端销售数据 | 稽核和动销分析的"独立真相来源" |
| Sell-through rate | 动销率,货上架后被买走的速度 | Q1 判断 IP x 品类组合是否值得续约 |
| SKU (Stock Keeping Unit) | 最小库存单元,即一款具体的商品 | `product_sku` 表的粒度 |
| Royalty report | 被授权商按季自报的版税流水 | 陷阱 2 的"自报"一侧 |
| Royalty audit | 版税稽核,用独立数据核实自报数字 | 陷阱 2 的"核实"一侧 |
| Variance | 差异(自报 vs 稽核推算) | 稽核结论的核心指标 |
| Streaming popularity index | 本数据集的流媒体热度周度指数(0-100 量表) | Q3 滞后分析的领先指标 |
| Season premiere | 新一季首播 | 触发热度峰值的典型事件 |
| Lag / lead time | 滞后期 | Q3 的核心概念——热度峰值领先零售销量峰值多少周 |
| Compliance score | 被授权商合规评分 (0-100) | `licensee` 表内部字段,驱动陷阱 2 和陷阱 4 的群体划分 |

## 9. 关键指标与公式

下面是 SQL 查询里用到、或读者应当知道的指标。公式用通俗记法(SQL 风格伪代码),并注明输入和口径约定。

**动销与续约**

```
weekly_sell_through_units(sku, channel, week) = pos_sell_through.units_sold        -- 最小粒度
total_units(ip, category)  = SUM(units_sold) 按 IP x 品类聚合                        -- Q1 用
total_revenue(ip, category) = SUM(net_wholesale_revenue_usd) 按 IP x 品类聚合          -- Q1 用
```

**版税稽核**

```
pos_derived_net_sales(agreement, period) = SUM(net_wholesale_revenue_usd)
    WHERE product_sku.license_agreement_id = agreement
      AND week_start_date IN [period_start, period_end)                             -- 跨所有渠道, 不区分是否授权
pos_derived_royalty  = pos_derived_net_sales × royalty_rate_pct / 100
variance_usd  = pos_derived_royalty − reported_royalty_due_usd                       -- 正值 = 疑似低报
variance_pct  = variance_usd / pos_derived_royalty × 100
```

**保底金额达成 (MG pacing)**

```
elapsed_fraction = (REFERENCE_DATE − contract_start_date) / (contract_end_date − contract_start_date)  -- 上限 1.0
prorated_mg_target = minimum_guarantee_usd × elapsed_fraction
cumulative_royalty_owed = SUM(reported_royalty_due_usd) 该合同全部已提交的版税报告
pacing_ratio = cumulative_royalty_owed / prorated_mg_target
```

**越权铺货**

```
is_authorized(agreement, channel) = EXISTS(license_agreement_channel WHERE license_agreement_id=agreement AND retail_channel_id=channel)
unauthorized_revenue_share = SUM(net_wholesale_revenue_usd WHERE NOT is_authorized) / SUM(net_wholesale_revenue_usd)  -- 按被授权商聚合
```

**热度-动销滞后(事件对齐法)**

```
relative_week(event, week) = ROUND((week − event.premiere_week) / 7 天)
avg_units(relative_week) = AVG(units_sold) 按 relative_week 聚合, 跨所有首播事件           -- Q3 用, 找峰值出现在哪个 relative_week
```

> **口径说明(避免下游 SQL 打架):**
> - `pos_derived_net_sales` 在版税稽核里**跨所有渠道**求和(不区分授权/未授权),因为稽核关心的是"被授权商到底卖了多少、该交多少版税",而不是"卖得合不合规"——那是 Q4 单独回答的问题。
> - `pacing_ratio` 只对 `contract_status = 'active'` 的合同计算才有业务意义;已到期或已终止的合同不应再被要求"追赶进度"。
> - `elapsed_fraction` 恒定上限为 1.0——合同到期后不能再无限期累积"应付进度"。
> - 版税季度 (`report_period_start_date` / `report_period_end_date`) 是**合同季度**(从 `contract_start_date` 起每 91 天一期),不是自然日历季度。跨合同比较"哪个季度"没有意义,只能在单一合同内部按期数比较。
