## 1. 公司:StreamCast Media 是谁

**StreamCast Media** 是一家总部位于**美国纽约 (布鲁克林)** 的**程序化播客广告平台 (Programmatic Podcast Ad Platform)**。它本身**不生产播客内容**,而是给 150+ 档独立播客节目提供"把听众注意力变成钱"的技术底座和销售渠道。可对标的真实公司:Spotify 旗下的 Megaphone、Acast、Art19、Audacy —— 但 StreamCast 是一家**虚构公司**,本数据集里的一切都是模拟数据。

一句话定位:StreamCast 是**"播客界的广告交易中间商"** —— 一头连着**流量供给侧 (播客主播)**,一头连着**广告需求侧 (品牌方)**,用实时拍卖撮合双方的广告交易,然后抽佣。在广告技术 (ad-tech) 行话里,这种角色叫 **SSP (Supply-Side Platform, 供给方平台)**。

**公司体量 (数量级):**

| 维度 | 量级 |
|------|------|
| 员工 | ~120 人 |
| 合作播客节目 | 150+ 档 |
| 月度触达听众 | 数百万级 |
| 年处理广告交易额 | 数千万美元级 |
| 成立时间 | ~6 年前 |

**起源故事 (一句话):** StreamCast 成立的初衷,是让那些没能力自建广告销售团队的**独立播客主播**,也能接入原本只对大网络开放的程序化广告需求 —— 用技术把"长尾内容"的广告库存盘活。

**和你分析工作相关的组织架构:**

| 角色 | 关心什么 |
|------|---------|
| **CFO / 财务** | 平台总营收、净抽佣、主播分成总额 |
| **VP of Monetization (变现副总裁)** | 定价策略、填充率、库存利用率 —— 你的报告很多最终汇给 TA |
| **Revenue Operations (RevOps) 团队** | 日常运营指标、仪表盘 —— **你直接汇报的团队** |
| **Account Executive (AE, 客户经理)** | 自己负责的广告主的续约率、预算消耗 |
| **Content Partnerships (内容合作 BD)** | 签哪类节目、主播的 RPM 是否有竞争力 |
| **Pricing / Auction 团队** | 拍卖机制是否健康、底价定得对不对 |
| **UX / Retention (体验与留存) 团队** | 广告会不会把听众气走 |

## 2. 商业模式:StreamCast 怎么赚钱

StreamCast 的核心收入是**广告抽佣 (take-rate)**。整条变现链路是:

```
1. 广告主在平台充值预算,设置投放目标
   (例如:"投 25-34 岁、加州/纽约、科技播客的听众")
        │
        ▼
2. 听众打开 App 收听播客,播放到广告位 (pre-roll / mid-roll / post-roll)
        │
        ▼
3. 平台在 50 毫秒内发起实时竞价 (RTB),所有匹配的广告主出 CPM 价
        │
        ▼
4. 出价最高者赢得广告位,但只付"第二高价 + $0.01" (二价拍卖)
        │
        ▼
5. 广告动态插入到播客流里播给听众
        │
        ▼
6. 平台向广告主收费,扣 30% 平台佣金,剩下 70% 按周/月结算给主播
```

**收入公式 (必须记住):**

```
平台日总营收 = SUM(每次广告曝光的成交 CPM) ÷ 1000
平台净收入   = 平台日总营收 × 30%   (平台抽佣)
主播分成     = 平台日总营收 × 70%   (创作者拿走)
```

**单位经济 (unit economics):**

- **抽佣率固定 30% / 70% 分成** —— 这是 Spotify、Acast 等行业惯例,StreamCast 沿用。
- 收入完全取决于两个杠杆:**卖出多少次曝光 (量)** × **每次曝光卖多少钱 (eCPM)**。
- 因此 StreamCast 的利润最终取决于三件事:**填充率高不高 (库存别空着)、单价定得对不对 (别把值钱的库存贱卖)、听众别被广告气走 (流失=未来库存消失)**。

**谁是买方:** 广告主横跨多个行业 (vertical) —— SaaS、FinTech、CPG (快消)、E-commerce (电商)、Automotive (汽车)、Healthcare (健康) 等。不同行业的广告主抢的人群不一样:SaaS/FinTech 死磕 `Tech_Enthusiast` / `Finance_Savvy` 标签,CPG 追 `Foodie` / `Health_Conscious`。

**这门生意的四大永恒矛盾** (数据分析最有价值的发力点):

| 矛盾 | 拉力 A | 拉力 B | 数据如何帮忙 |
|------|--------|--------|--------------|
| 收入 vs 体验 | 多塞广告 → 收入多 | 多塞广告 → 听众烦 → 流失 | 找出每集塞几个广告 ROI 最高的甜蜜点 |
| 填充率 vs 单价 | CPM 卖高 → 单次曝光赚多 | CPM 卖高 → 广告主嫌贵 → 库存空置 | 动态定价:旺时高价、淡时打折 |
| 精准 vs 规模 | 投定向人群 → 转化率高 | 投定向人群 → 触达量小 → 预算花不完 | 衡量定向溢价是否带来等量回报 |
| 平台 vs 创作者 | 平台想多抽 | 创作者要 70% 才活得下去 | 帮主播看清"哪类内容 RPM 高" |

## 3. 行业概览:程序化播客广告这门生意

如果你来自别的行业,这一节帮你把"播客广告这个市场到底在干什么"理顺。

**这个行业创造什么价值?**
传统播客广告是**主播口播 (host-read)** + **广告录死在音频文件里 (baked-in)** —— 三年前的老节目重听一遍,广告还是三年前那个,广告主没法再付钱,也没法定向、没法衡量效果。程序化播客广告行业用 **DAI (动态广告插入)** 技术,把广告位变成"空白占位符",听众每次播放时实时插入当下竞价赢得的广告。这带来三个革命:**老节目能持续变现、广告能定向到具体人群、同一个库存能反复二次销售并衡量效果。**

**行业里的玩家分类** (都用一般名词,不点名真实公司):

| 角色 | 干什么 | StreamCast 在哪 |
|------|--------|----------------|
| **SSP (供给方平台)** | 帮媒体/主播卖广告库存 | **← StreamCast 是 SSP** |
| **DSP (需求方平台)** | 帮广告主程序化采购库存、做出价优化 | 广告主用的工具 |
| **播客托管平台 (hosting)** | 存储分发音频、提供 DAI 能力 | 上游/有时一体 |
| **广告网络 (ad network)** | 打包一批库存卖给广告主 | 竞争/补充 |
| **测量与归因 (measurement)** | 衡量广告带来的转化 | 第三方供应商 |

**北美的监管与行业规范** (你写报告时可能引用到):

- **FTC (Federal Trade Commission, 联邦贸易委员会):** 管"广告不能虚假宣传",对带货/口播有 endorsement guides (代言披露规则)。
- **CCPA / CPRA (加州消费者隐私法):** 限制平台如何收集、使用听众数据 —— 这就是为什么 `listener` 表只能用匿名 UUID,不能存真实身份。
- **COPPA (儿童在线隐私保护法):** 面向 13 岁以下用户的内容有特殊限制。
- **IAB Tech Lab 标准 (VAST 等):** 行业自律的技术规范,统一广告投放/计数口径。
- **加拿大:** PIPEDA (隐私) 与 CASL (反垃圾营销) —— 当业务扩展到加拿大市场时适用。

**当下塑造行业的宏观力量:**

1. **大厂整合:** 流媒体巨头持续收购播客 ad-tech,中间平台面临"被并购或被挤压"的压力。
2. **从 baked-in 到 DAI:** 动态插入成为主流,程序化份额逐年上升。
3. **隐私收紧 + Cookie 退场:** 第三方标识符消失,逼平台转向**上下文定向**和**第一方数据** (听众标签 `listener_segment` 就是第一方数据资产)。
4. **AI 渗透:** AI 用于广告匹配、动态创意生成、出价优化 —— 让"精准 vs 规模"的权衡有了新解法。

## 5. 这个项目要回答的业务问题

下面 5 个问题是本数据集的"主线剧情"。ER 文档里的表结构、generator 埋的数据分布、SQL 文档里的查询,全都是为了回答它们而存在的。

**Q1. mid-roll 的底价是不是定低了?哪些库存被严重低估、该提价?**
业内"公认"mid-roll 最值钱 (完播率最高),底价定成 pre-roll 的 1.67 倍 ($25 vs $15)。但如果实际成交价远超底价,说明平台"把钱留在了桌上"。→ 对应 SQL Query 1、Query 6。

**Q2. 凌晨和周末的广告位为什么大量空置?动态定价能挽回多少收入?**
听众在低谷时段并没少听,但 fill rate 明显偏低 = 库存浪费 = 收入损失。能不能淡时降底价、吸引预算敏感的中小广告主进场填空?→ 对应 Query 2、Query 4。

**Q3 / Q4. 高价值人群标签的定向溢价,是否真的带来等量回报?**
`Tech_Enthusiast` 这类标签让 CPM 比泛投高 30-50%,广告主多花的钱值不值?平台又能不能拿这个数据去给销售做 pitch?→ 对应 Query 3 (平台视角)、Query 9 (广告主视角)。

**Q5. 广告频次到多少会引发广告疲劳、把听众气走?**
同一听众被同一广告主反复轰炸,会狂跳广告、甚至流失。频次封顶 (frequency cap) 该设几次?→ 对应 Query 17、Query 19。

**Q6. 二价拍卖机制有没有被正确执行 (没有 bug 导致超收)?**
理论上赢家只付"第二高价 + $0.01"。如果平均超收远超 $0.05,说明计费代码有 bug,广告主会投诉。→ 对应 Query 22。

**次要问题** (同样有查询覆盖):广告主预算消耗与 pacing 是否健康 (Query 5、Query 23)、单 campaign / 单素材的 ROI (Query 7、Query 8、Query 11)、主播 RPM 同行对标 (Query 13~16)、行业与节目分类的增长趋势 (Query 25、Query 26)。

## 7. 行业知识科普 (Podcast Ad 101)

完全没接触过数字广告 / 播客行业的话,先把这 5 个概念吃透,后面的数据全部秒懂。

### 7.1 三种广告位 (Ad Slot 类型)

| 位置 | 中文叫法 | 典型时长 | 听众完播率 | 基础 CPM | 为什么这么值钱 |
|------|---------|---------|------------|----------|----------------|
| **Pre-roll** | 片头广告 | 15-30 秒 | ~88% | $15 | 听众刚打开,注意力最集中 |
| **Mid-roll** | 中插广告 | 30-60 秒 | ~95% | **$25** (最贵) | 听众已投入,不会为跳广告而弃听后半集 |
| **Post-roll** | 片尾广告 | 15-30 秒 | ~42% | $8 (最便宜) | 很多人听完正片就关了,触达率最低 |

**为什么 mid-roll 最值钱?** 因为听众已经投入了 10+ 分钟,**沉没成本**让他们不会因为一个广告就放弃后半集 → 完播率最高 → 广告信息传递最完整。这是整门生意里最赚钱的库存,平台、主播、广告主全盯着它。

### 7.2 实时竞价 (RTB, Real-Time Bidding)

每当一个听众即将播放到广告位的那一瞬间 (典型 50-100 毫秒内),平台会:打包听众画像 (年龄、地区、兴趣标签、收听历史) → 广播给所有可能感兴趣的广告主 → 每个广告主决定出不出价、出多少 → 价高者得,广告插入播放。**全程自动化,人不参与每一笔交易。**

### 7.3 第二价格拍卖 (Second-Price / Vickrey Auction)

这是**整个数字广告行业的核心机制**,务必搞懂:

- **场景:** 5 个广告主竞价同一个广告位,报价 A $30 / B $25 / C $20 / D $15 / E $10。
- **赢家:** A (出价最高)。
- **实付:** **$25.01** (第二名的价 + $0.01),**不是 $30**!

**为什么这么设计?** 让广告主**如实出自己的心理价位**,而不用费心算"我该比第二名高出多少"。这是诺贝尔奖级的机制设计,理论上能让市场达到最优效率。作为分析师,你要盯的是:平台是不是**真的**按第二价格收费?(对应字段 `winning_bid_cpm` vs `actual_charge_cpm`。)

### 7.4 动态广告插入 (DAI, Dynamic Ad Insertion)

老式播客把广告录死在音频里;DAI 让广告位变成空白占位符,听众每次播放时实时插入当下竞价赢得的广告。同一集节目,A 听众听到耐克广告、B 听众听到麦当劳广告。这让**老节目持续变现、广告可定向、库存可二次销售**,是这门生意的技术底座。

### 7.5 三方关系链

```
[广告主]            [StreamCast 平台]            [播客主播]            [听众]
  ↓                       ↑                         ↓                  ↓
预算 $$$  →  竞价撮合 + 抽佣 30%  →  分成 70%  ←  注意力 + 收听时长
```

平台两头都要伺候好:广告主 (花钱方) 和主播 (流量方);**听众体验是双方共同的护城河** —— 听众跑了,库存就消失了。

## 8. 术语表 (Glossary)

数字广告行业的"普通话"。所有会议、PPT、邮件都用这些英文缩写,你必须背下来。每条 = **英文术语 + 大白话解释 + 为什么在本数据集里重要**。

### 8.1 价格与变现类

| 术语 | 全称 | 大白话 | 为什么重要 |
|------|------|--------|-----------|
| **CPM** | Cost Per Mille | 每 1000 次广告播放,广告主付多少钱 (= 平台的售价) | 平台收入的基本单价;贯穿几乎所有查询 |
| **eCPM** | effective CPM | 经过实际拍卖 + 二价折扣后的**真实平均成交价** | 比"底价"更能反映库存的真实市场价值 (Q1/Q6) |
| **RPM** | Revenue Per Mille | 每 1000 次**节目播放**,**主播净赚**多少 (扣 30% 后) | 主播视角的变现效率;量级是十几到几十美元 (Q13/Q14) |
| **Base CPM** | 基础 CPM / 底价 | 平台给每种广告位设的最低起拍价,出价不得低于此 | 提价决策的基准线 (Q1/Q6) |
| **Take Rate** | 抽佣率 | 平台从总营收里抽走的比例 (这里固定 30%) | 平台净收入 = 总营收 × take rate |

> **CPM vs RPM 最容易混:** CPM 是**广告位的价格** (广告主付的);RPM 是**节目的变现效率** (主播净赚的)。卖广告 CPM=$20 → 扣 30% → 主播拿 $14 → 按每次播放约 1.5 个广告折算,RPM ≈ $9-14/千次播放。

### 8.2 效果与回报类

| 术语 | 全称 | 大白话 | 为什么重要 |
|------|------|--------|-----------|
| **Completion Rate** | 完播率 | 听完整个广告的比例 | 反映广告质量 + 听众粘性 (Q1/Q8) |
| **Skip Rate** | 跳过率 | 中途快进掉广告的比例 | 越高越说明广告烦人 (Q17/Q18) |
| **CTR** | Click-Through Rate | 点击广告链接的比例 (播客约 0.5-1.5%) | 衡量广告吸引力;本数据集已建模 `was_clicked` |
| **Conversion Rate** | 转化率 | 看完广告后真的下单/注册的比例 | 终极效果;已建模 `converted` |
| **CPA** | Cost Per Acquisition | 花多少钱获得一个新客户 | 广告主最关心的最终 KPI (Q7) |
| **CPCV** | Cost Per Completed View | 花多少钱让一个人**完整听完**广告 | 比 CPM 更严格的效果口径 (Q8/Q11) |
| **ROAS** | Return On Ad Spend | 花 1 块广告费赚回几块钱 | 广告主判断投放值不值 (SaaS 健康线 ROAS≈3) |
| **LTV** | Lifetime Value | 一个客户终生贡献多少营收 | 判断 CPA 划不划算 (LTV/CPA>3 通常安全) |

### 8.3 库存与拍卖类

| 术语 | 全称 | 大白话 | 为什么重要 |
|------|------|--------|-----------|
| **Fill Rate** | 填充率 | 广告位有没有空着 (成交数 ÷ 可用数) | 库存利用率,健康值 90%+ (Q2/Q4) |
| **Inventory** | 广告库存 | 一段时间内可投放的广告位总数 | 平台的"货架" = 播放次数 × 每集广告位数 |
| **Win Rate** | 赢拍率 | 广告主出价 N 次赢了几次 | 广告主调出价策略的依据 (Q10/Q12) |
| **Bidders per Auction** | 单场出价者数 | 一次拍卖平均几个人抢 | 6+ = 卖方市场;<2 = 库存被低估 (Q21) |
| **Bid Spread** | 出价分散度 | 一场拍卖里最高价 - 最低价 | 越大说明估值分歧越大、拍卖越有用 (Q21) |
| **Audience Match Score** | 定向匹配度 (0-1) | 听众多大程度符合广告主的定向条件 | 驱动出价溢价 (Q9) |
| **Pacing** | 预算调配 | 让预算在投放期内匀速消耗 | 太快会提前耗尽,太慢花不完 (Q23) |

### 8.4 机制与行业概念

| 术语 | 全称 | 大白话 |
|------|------|--------|
| **RTB** | Real-Time Bidding | 50 毫秒内完成的自动化广告拍卖 |
| **DAI** | Dynamic Ad Insertion | 播放时实时插广告 (老节目可二次变现) |
| **SSP** | Supply-Side Platform | 媒体/主播用的程序化售卖平台 (StreamCast 是 SSP) |
| **DSP** | Demand-Side Platform | 广告主用的程序化采购平台 |
| **CTA** | Call To Action | 广告里的"立即下单 / 访问官网"号召 |
| **Second-Price Auction** | 二价拍卖 / Vickrey 拍卖 | 赢家付第二高价 + $0.01,鼓励如实出价 |
| **Frequency Cap** | 频次封顶 | 限制单听众一段时间内看同一广告主的次数 |
| **Ad Fatigue** | 广告疲劳 | 同一广告听太多次后反感、跳过率上升 |
| **Brand Safety** | 品牌安全 | 防止广告出现在不当内容旁边 |
| **Competitor Exclusion** | 竞品屏蔽 | 广告主要求不和竞品出现在同一集 (如可乐 vs 百事) |
| **Premium (ad-free)** | 会员免广告 | 会员听众 / 会员专享节目不产生广告曝光 |

## 9. 关键指标公式 (Metrics with Formulas)

下面给出本数据集所有重要指标的口径。**两套口径并存时,这里明确选一套**,避免不同查询算出不一致的数。

### 9.1 平台变现

```
Total Revenue (总营收)      = SUM(ad_impression.actual_charge_cpm) / 1000
Platform Net Revenue (净收) = Total Revenue × 30%
Creator Payout (主播分成)   = Total Revenue × 70%
eCPM (实际成交均价)         = AVG(ad_impression.actual_charge_cpm)
                              ( = Total Revenue / 曝光数 × 1000, 两者等价)
RPM (主播每千次播放净收入)  = (Creator Payout / play_session 数) × 1000
```

> **Fill Rate 有两套口径,务必声明用哪套:**
> - **结算口径 (`revenue_settlement.fill_rate`):** 分母 = 听众**实际触达到**的广告位 (没播放到的 mid/post-roll 不计入)。数值偏高。
> - **现算口径 (Query 2 / Query 4):** 分母 = **全部"会话-广告位对"** (含听众没听到的位)。数值偏低。
> 两者都 ≤ 100% 但口径不同,跨查询对比时必须说明用的是哪一套。

### 9.2 广告主表现

```
Spend (campaign 已花)       = SUM(actual_charge_cpm) / 1000   (限该 campaign)
Budget Utilization % (消耗率)= Spend / window_budget_usd × 100
                              ( 用 window_budget_usd 而非 total_budget_usd,
                                否则 60 天采样下消耗率恒≈0%, 见 ER 文档说明 )
Completion Rate             = SUM(was_completed) / COUNT(*)
Skip Rate                   = SUM(was_skipped) / COUNT(*)
CPCV                        = Spend / SUM(was_completed)
CTR                         = SUM(was_clicked) / COUNT(*)
Conversion Rate            = SUM(converted) / COUNT(*)
CPA                        = Spend / SUM(converted)   ( SUM(converted)=0 时为 NULL )
Win Rate (per campaign)    = SUM(won_auction) / COUNT(*)   (在 ad_auction_log 上)
```

### 9.3 主播 / 节目

```
Plays per Episode   = COUNT(play_session)   (按 episode 分组)
Avg Completion %    = AVG(play_session.completion_percentage)
Daily RPM           = revenue_settlement.rpm
Category RPM 对标    = 同分类内 RPM 的 avg / min / max
                      ( 注: SQLite 原生无 PERCENTILE_CONT, 中位数/分位需 NTILE 或外部算 )
```

### 9.4 拍卖市场

```
Avg Bidders per Auction = COUNT(ad_auction_log) / COUNT(DISTINCT impression_id)
Bid Spread (per auction)= MAX(bid_cpm) - MIN(bid_cpm)
Winner's Savings        = winning_bid_cpm - actual_charge_cpm
Second-Price Premium    = actual_charge_cpm - 第二名出价   ( 应 ≈ $0.01 )
```

### 9.5 听众体验

```
Ad Frequency        = COUNT(ad_impression) / 去重听众数   (按时段)
Ad Fatigue Score    = 同广告主曝光数 × skip_rate
Premium Conversion  = is_premium_subscriber 听众数 / 全部听众数
```
