# 搜索广告归因分析 Agent 数据集: 业务背景与行业科普

本文件是 `search_advertising_attribution_agent_large` 数据集的第一份文档，目的是把整套数据放回它所服务的真实业务里。后面三份文档分别讲数据结构（`02-..._er_document-cn.md`）、查询示例（`03-..._sql_queries-cn.md`）和数据生成脚本（`04-..._data_generator-cn.py`）。读完本文件，一个从没接触过付费搜索的人应该能在团队站会上听懂大家在聊什么。

读者画像是聪明的外行，不是行业专家。可以把自己想象成刚加入项目、还没开始第一次站会的新实习生。本文件会一次性把公司、行业、项目、要解决的问题和满屏的英文黑话讲清楚。市场默认是北美：公司在美国，货币是 USD，客户和城市都在北美，监管机构是美国或加拿大的。中文只是叙述语言，业务本身是北美的。

## 1. 公司画像

故事的主角是一家虚构的北美媒介代理控股集团，名字叫 **Lumina Reach Media Group**，总部在伊利诺伊州芝加哥。它不对应任何真实公司。

Lumina Reach 不是一家单独的代理，而是一个代理网络。它旗下有 15 家成员代理（数据里的 `agency` 表），按服务能力分成 Platinum、Gold、Silver、Standard 四个等级。这些成员代理合在一起，替 80 个广告主品牌（`advertiser` 表，覆盖零售、旅游、金融、医疗、汽车、保险、B2B SaaS、教育、地产、餐饮十个行业）运营付费搜索投放。其中大约 80% 的广告主由网络内某家代理托管（`agency_client` 桥接表），剩下约 20% 是品牌内部团队自营，但同样把数据汇总进集团这套统一报表平台。

规模上给个量级感：整个网络几百号人，集团中央有一个十来人的分析团队，负责把分散在各成员代理的投放数据汇总成跨组合视图。数据集覆盖的窗口里，这 80 个广告主在 Google Ads 和 Microsoft Advertising 上的付费搜索花费在数千万美元量级。投放层级上有约 800 个 campaign、4,200 个 ad group、42,000 个关键词，每天产生十几万行投放表现数据。

组织里几个会在后面查询里被点名的角色：集团 CMO（看跨组合的行业分布和归因真相）、成员代理的 account manager（盯自己名下广告主的预算节奏）、面向广告主的 campaign 经理和付费搜索分析师（做日常优化），以及做否定关键词复盘的运营专员。你将扮演的就是中央分析团队里的一名数据分析师。

## 2. 商业模式

Lumina Reach 怎么赚钱，一句话讲清楚：它按所管理的广告花费收一笔代理费。

具体机制是这样。广告主把每月几千到几十万美元的付费搜索预算交给某家成员代理打理。代理负责搭建账户、选关键词、设出价策略、盯预算节奏、做转化跟踪和报表。作为回报，代理按管理花费的一个百分比抽成，数据里这个比例存在 `agency_client.fee_percentage`，区间是 8% 到 20%。花得多、服务等级高的客户，费率谈法不同；也有少数客户走固定年费而非比例抽成。这意味着集团的收入直接挂钩两件事：管理了多少广告花费，以及把这些花费管得有多好（管得好客户才会续约、加预算）。

广告主那一侧的账要分开看。广告主关心的不是代理费，而是每一块广告花费能不能换回足够的生意。他们盯两个效率指标：CPA（cost per acquisition，单次转化成本，等于总花费除以总转化数）和 ROAS（return on ad spend，广告支出回报率，等于转化价值除以花费）。一个 CPA 50 美元、ROAS 4.0 的投放是健康的，每花 50 美元带回 200 美元客户价值；一个 CPA 200 美元、ROAS 0.8 的投放在亏钱，需要干预。代理的本事，就体现在能不能把客户的 CPA 压下去、ROAS 抬上来。

行业的客单价差别很大，这会直接拉开各行业的 ROAS。地产、金融、保险、汽车这类高客单价行业，一次转化值几百到两千美元；餐饮、零售这类低客单价行业，一次转化只值十几到几百美元。所以同样花一块钱，地产客户的 ROAS 天然比餐饮客户高，这不是代理水平的差距，是行业本身的经济结构。后面看跨行业报表时要记住这一点。

## 3. 搜索广告行业全景

把一个从别的行业来的人领进门，先讲清楚付费搜索这门生意到底在交易什么。

当你在搜索引擎里输入一个查询，比如 `cheap flights to maui`，引擎在同一页返回两种结果。一种是自然结果（organic），按相关性算法排序，免费。另一种是赞助结果（sponsored，标着 Ad 或 Sponsored），通过实时竞价选出，广告主为此付费。搜索广告就是这些赞助位的生意。广告主事先告诉引擎，如果有人搜某个词、我愿意出最高多少钱让广告展示给他；一条匹配的查询进来时，引擎在所有竞争这个词的广告主之间瞬间办一场拍卖，按出价乘以质量得分排序，展示排名最高的几个。

这个市场有三方。用户想要和查询相关的答案；广告主想要在可承受价格下的点击和转化；搜索引擎想要拍卖收入加上长期口碑（广告太烂用户会跑）。本数据集站在广告主这一侧，更准确说，是替广告主运营投放的代理视角。

主要的玩家类别（不点名真实公司）有：搜索引擎本身（数据里是 Google Ads 和 Microsoft Advertising 两家）、像 Lumina Reach 这样的媒介代理、广告主的品牌内部营销团队，以及提供统一管理平台的技术方。北美市场 Google 一家独大，Microsoft 体量小但出价竞争也小，常被用来补量。

监管和合规这几年是悬在头顶的事。美国 FTC（联邦贸易委员会）管虚假广告和欺骗性宣传；加州 CCPA 和各州陆续出台的隐私法管用户数据怎么用；浏览器逐步淘汰第三方 cookie、苹果的隐私新规等等，统称信号丢失（signal loss），直接动摇了跨网站追踪用户、做精准归因的根基。再加上针对 Google 搜索市场支配地位的反垄断诉讼，整个行业的底层假设都在松动。

塑造当下的几股宏观力量值得记住。一是自动化和 AI 出价（Smart Bidding）正在把人工调价的活儿接过去，分析师的工作从"调出价"转向"审计机器调得对不对"。二是信号丢失逼着大家从确定性追踪转向建模归因。三是把预算分散到多个引擎、多个渠道之后，归因（到底是哪个触点促成了转化）从一个学术问题变成了天天要回答的预算分配问题。本数据集的核心，正是最后这件事。

## 4. 你的角色与项目

你是 Lumina Reach 集团中央分析团队的一名数据分析师。你不直接操盘某个广告主的投放，而是坐在所有成员代理和广告主之上，做跨组合的分析和报表。

你的产出主要有三类。一是给集团 CMO 和季度评审准备的跨组合表现材料（哪些行业花得多、哪些代理等级 ROAS 强、组合整体效率趋势）。二是给成员代理 account manager 和 campaign 经理用的运营看板（预算节奏、受预算约束的 campaign、超出 Target CPA 的 campaign）。三是最有技术含量的归因 what-if 分析：同一批转化，换不同归因模型来分配信用，渠道的价值排序会怎么变。这一类直接影响下个季度的预算往哪个渠道倾斜。

这些产出的受众包括集团 CMO、成员代理负责人、面向广告主的客户团队，偶尔还有广告主自己。报表口径必须前后一致，因为不同人会拿同一个指标做不同决策，口径一乱，结论就互相打架。

整套数据锚定在一个固定的参考日期（`REFERENCE_DATE`），所有"最近 7 天 / 30 天"之类的时间窗口都从这个日期往回算，而不是用查询当天的真实日期。这样无论数据集多久前生成，跑出来的结果都稳定可复现。技术上，参考日期由 `v_reference_date` 视图暴露，取的是 `daily_stats` 里最新的 `report_date`。

## 5. 这个项目要回答的业务问题

整个数据集是围绕下面五个具体问题搭起来的。后面 SQL 文档里的 20 个查询，每一个都能追溯到其中某个问题。

**问题一，归因真相。** 大多数广告主默认用末触归因（last click），也就是把一笔转化的全部功劳记给用户转化前点的最后一个广告。问题是，末触会系统性低估上漏斗渠道（Display、Paid Social）的贡献，高估临门一脚的渠道（Paid Search、Direct）。如果只看末触报表来分预算，可能会把启动用户旅程的渠道活活饿死。我们需要把同一批转化在六种归因模型下都算一遍，量化这个偏差到底有多大。这是项目最核心的问题，数据集也因此得名。

**问题二，预算效率。** 哪些 campaign 因为日预算不够，把本该拿到的展示拱手让人（`lost_is_budget` 高）？哪些 campaign 花得超过计划、节奏失控（pacing 远超 100%）？前者是加预算就能直接买到更多展示的"轻松赚钱"清单，后者是要踩刹车的清单。

**问题三，跨引擎效率。** 组合被 Google 主导（约 75% 花费），Microsoft 只占约 25%。Microsoft 的点击更便宜，但转化率也更低。把两边的 CPA、ROAS 摆一起看，Microsoft 到底值不值得加投？

**问题四，浪费治理。** 哪些搜索词花了钱却零转化，是否定关键词排除的候选？哪些关键词 Quality Score 偏低、拖高了所在 campaign 的成本？哪些 ad group 的广泛匹配溢出比例过高，说明匹配类型设得太松？这些都是把预算从浪费里夺回来的抓手。

**问题五，代理与组合结构。** 按代理等级看，Platinum 代理的 ROAS 真的比 Standard 高吗？各 IAB 行业的花费、广告主数、ROAS 分布是什么样？这驱动集团层面的人才分配和客户组合决策。

## 6. 数据范围速览

时间上，事实数据是近期快照，账户结构数据是历史累积。`daily_stats`（每日投放表现）覆盖参考日期往前 90 天；`search_term_report`（搜索词表现）覆盖往前 30 天；`conversion`（转化事件）覆盖 90 天；账户结构（campaign、关键词等）的创建时间散落在过去 18 个月内。

数据量用大白话说：80 个广告主、约 800 个 campaign、约 4,200 个 ad group、约 42,000 个关键词、约 12,500 条文字广告。事实层更大，约 16.5 万行每日投放表现、5,000 个转化事件、约 1.54 万个归因触点、约 31.8 万行搜索词记录。总计约 57 万行，分布在 21 张表里。

几个有意为之的范围收窄要先说明。整个数据集只有一种货币（USD）和一个时区（America/Los_Angeles），因为虽然真实 SA360 是多货币多时区部署，但本数据集不想让货币换算和时区对齐分散教学注意力。只建模两家引擎（Google Ads 和 Microsoft Advertising），第三家 Yahoo Japan 被删掉了，因为它是日本市场专用、不服务美国广告主。市场限定北美。这些收窄都是为了让数据集聚焦在归因、出价、预算这三条主线上，而不是被部署细节淹没。

## 7. 行业知识科普

这一节是外行真正看懂数据前需要的那三十到六十分钟背景。读完它，前面提到的黑话和后面查询里的列名都会变得有意义。

### 账户树: 投放是怎么组织的

每个广告主的账户都按经典的 Google Ads / SA360 五层结构组织，从上到下是：广告主（advertiser，付钱的公司）、引擎账户（engine_account，每个广告主在每家引擎上一个账户）、campaign（投放系列，是预算包加定向加状态的单位）、ad group（广告组，campaign 里的一个主题）、再往下分叉成 keyword（用户搜的词）和 text ad（用户点之前看到的文字广告）。

举个具体例子帮助记忆。广告主是 Acme Travel Co.（一家在线旅游公司），它有一个 Google Ads 账户和一个 Microsoft Advertising 账户；账户下有个 campaign 叫 "Acme Cancun Hotels Mobile"（只投美国、日预算 2,000 美元、用 Target ROAS 出价）；campaign 下有个 ad group 叫 "Cancun All-Inclusive Resorts"；ad group 下挂着关键词 `all inclusive cancun`（完全匹配、最高出价 4.50 美元）和一条文字广告。用户搜 `all inclusive cancun` 时，引擎把它匹配到这个关键词，办一场拍卖，Acme 赢了就展示它的广告，用户点了 Acme 就按拍卖出清价付费。

### 钱怎么流动

广告主按点击付费（CPC，cost per click），不是按展示付费。广告展示了但没人点，广告主不花钱。每次点击实际付的钱通常小于广告主设的最高出价，它是击败下一名竞争者所需的最小金额。也有按转化付费、按 ROI 优化的变种出价方式，但底层付费单元是点击成本。

每一次点击的扣费变成引擎的收入，这就是 Google 和 Microsoft 从搜索里赚钱的方式。广告主希望点击转化成付费客户，客户的生命周期价值（LTV）能覆盖点击成本加合理毛利。代理则按管理花费抽成。三方各分一块。

### Search Ads 360 是什么

大广告主很少只在一家引擎投放。一家美国零售商可能用 Google Ads 抓主流需求，再用 Microsoft Advertising 接住 Bing 和 Edge 的用户。分别登录每家引擎的后台非常痛苦：跨引擎花费没法对比，出价策略不能复用，转化跟踪要走两套管道。

Search Ads 360（简称 SA360）是 Google 的企业级平台，专门解决这个问题。广告主把每家引擎的账户接进 SA360，它就成了统一入口，用来管投放、委托出价、分配预算、跨引擎统一转化跟踪。代理几乎都在 SA360 里干活，因为他们通常同时管多个广告主在多家引擎上的投放。本数据集模拟的就是 SA360 这一层，是 80 个广告主在两家引擎上汇总后的组合视图，而不是单家引擎的视角。

### 展示份额: 我到底拿到了多少机会

Impression Share（展示份额，简称 IS）是个关键诊断指标。它回答的是：在所有我本可以参与的拍卖里，我的广告实际展示了多少比例？比如展示份额 70%，意味着有 30% 的机会我没拿到。

没拿到的部分能拆成两个原因。一是出价或质量不够（lost IS rank，排名输了），二是预算不够、当天钱花完了广告停投（lost IS budget，预算输了）。这两个加上拿到的展示份额，三者大致凑成 100%。这个拆解非常有用：如果损失主要来自预算，那加预算就能直接买到更多展示；如果损失来自排名，加预算没用，得改出价或提升质量得分。

搜索流量还有更细的位置指标。`search_top_is` 是广告出现在搜索结果首屏顶部的份额，`search_abs_top_is` 是出现在绝对第一位的份额。构造上这三个有序：绝对顶部份额 ≤ 顶部份额 ≤ 整体展示份额。要注意，这些位置份额指标只对搜索流量上报，Display、Video、Performance Max、Shopping 这些非搜索类 campaign 上是空值（NULL）。

### Quality Score: 引擎给你的关键词打分

Quality Score（质量得分，简称 QS）是引擎给每个关键词打的 1 到 10 分，综合了预期点击率、广告相关性、落地页体验三个子维度。分数高，同样的出价能换到更好的排名和更低的实际 CPC；分数低，要么多花钱要么排得靠后。

竞争越激烈的行业，质量得分越难拿。本数据集里保险、金融、地产这类高竞争垂直的 QS 分布整体偏低（平均 6 分上下），而 B2B SaaS、教育、餐饮这类低竞争垂直的 QS 偏高（平均 7 到 8 分）。所以"低 QS 关键词在哪个行业最集中"这种问题，答案是有结构的，不是随机噪声。

### 匹配类型与搜索词

关键词有三种匹配类型，从严到松是：完全匹配（Exact，只匹配几乎一模一样的查询）、词组匹配（Phrase，匹配包含这个词组的查询）、广泛匹配（Broad，匹配引擎认为相关的查询）。匹配越宽，能覆盖的查询越多，但也越容易匹配到不相关、不转化的词。

`search_term_report` 记的是用户真实输入、触发了广告展示的搜索词。这里有个重要现象叫广泛匹配溢出（broad-match overflow）：约 15% 的搜索词记录匹配不回任何一个已存关键词（`keyword_id` 为空），因为引擎服务的这条查询没直接命中库里的词。溢出比例过高，说明匹配类型设得太松，钱漏给了没人盯着的查询。

### 转化跟踪与多触点归因

当用户在广告主网站完成购买、注册之类的动作时，会触发一个 Floodlight 标签（SA360 的转化跟踪定义），生成一条转化事件（`conversion` 表）。

一笔转化往往不是一次点击促成的。用户可能先在 Display 上看到广告（首触），几天后搜了个品牌词点进来（中间触点），最后直接输网址下单（末触）。归因要解决的是：这笔转化的功劳，怎么分给沿途这些触点？本数据集为每个触点（`attribution_path` 表）同时存了六种归因模型的信用分配：

- 末触（Last Click）：全部功劳给最后一个触点。
- 首触（First Click）：全部功劳给第一个触点。
- 线性（Linear）：每个触点平分，N 个触点各得 1/N。
- 时间衰减（Time Decay）：越靠近转化的触点拿得越多，按几何级数衰减。
- 位置（Position Based）：首末各 40%，中间触点平分剩下的 20%；只有两个触点时退化成各 50%。
- 数据驱动（Data Driven）：本数据集里用归一化随机数模拟，不是真实 DDA 模型的输出，仅供学习者写六模型对比查询用。

每个触点还限制在转化所属广告主自己的账户子树内（不会出现跨广告主的触点），且只能落在转化前的回溯窗口（lookback window）之内。路径长度偏短，约 40% 的转化只有两个触点，长路径（5 到 6 个触点）很少见，这和真实归因数据一致。

### 一个容易踩的坑: 两种 conversion 不能混

数据集里 "conversion" 这个词出现在两个尺度完全不同的地方，绝对不能相加或逐行对比。`daily_stats.conversions` 是引擎按天聚合上报的转化数（报表里展示的那个值），16.5 万行加起来在百万级。`conversion` 表是 Floodlight 事件日志，只有 5,000 个单独事件，带显式价值和时间戳，用来做路径和归因分析。问"总共多少转化"这种问题，必须挑定一种口径用到底。

## 8. 术语表

下面把数据和查询里会用到的英文黑话逐个解释。每条给出英文术语、一句白话解释、以及它在本项目里为什么重要。缩写第一次出现时给全称。

**CPC (Cost Per Click，单次点击成本)。** 广告主为一次点击付的钱。它是付费搜索的基本计费单元，所有花费都由点击数乘以 CPC 累加而来。

**CPA (Cost Per Acquisition，单次转化成本)。** 获取一个转化（购买、注册等）花了多少钱，等于总花费除以总转化数。广告主衡量投放效率的头号指标，CPA 失控就要干预。

**ROAS (Return On Ad Spend，广告支出回报率)。** 花出去的每一块钱带回多少转化价值，等于转化价值除以花费。和 CPA 一起构成效率的两面，行业客单价高低会直接拉开 ROAS。

**CTR (Click-Through Rate，点击率)。** 点击数除以展示数。衡量广告创意和关键词相关性吸不吸引人，付费搜索的典型 CTR 在 1% 到 6%。

**Impression Share (展示份额，IS)。** 实际展示数占本可参与展示总数的比例。回答"我拿到了多少机会"，是预算和出价是否到位的核心诊断。

**Lost IS Budget / Lost IS Rank (因预算 / 排名损失的展示份额)。** 没拿到的展示份额里，分别归因于预算花完和出价排名不够的两部分。这个拆解决定了加预算有没有用。

**Quality Score (质量得分，QS)。** 引擎给关键词打的 1 到 10 分，综合预期点击率、广告相关性、落地页体验。分数高能换更低的实际 CPC，是优化关键词的重要抓手。

**Match Type (匹配类型)。** 关键词触发广告的宽松程度，分完全匹配（Exact）、词组匹配（Phrase）、广泛匹配（Broad）。越宽覆盖越广，但越容易引来不相关的查询。

**Bid Strategy (出价策略)。** 决定每次拍卖出多少价的规则。手动的有 Manual CPC、Enhanced CPC；自动的（Smart Bidding）有 Target CPA、Target ROAS、Maximize Conversions、Maximize Conversion Value、Maximize Clicks、Target Impression Share。

**Smart Bidding (智能出价)。** 引擎用机器学习自动调出价以命中某个目标（如 Target CPA）。分析师的活儿从手动调价变成审计机器调得准不准。

**SA360 (Search Ads 360)。** Google 的企业级跨引擎投放管理平台，本数据集模拟的就是这一层。

**Floodlight Tag (Floodlight 标签)。** SA360 里的转化跟踪定义，用户完成目标动作时触发，生成一条转化事件。每个标签声明一个广告主生产用的归因模型。

**Attribution Model (归因模型)。** 把一笔转化的功劳分配给沿途各触点的规则。本数据集存了六种：Last Click、First Click、Linear、Time Decay、Position Based、Data Driven。

**Lookback Window (回溯窗口)。** 转化往前回溯多少天内的触点才算数，本数据集取 7、14、30、60、90 天之一。触点的发生时间不能早于这个窗口。

**Touchpoint (触点)。** 用户在转化路径上的一次广告接触（展示、点击或浏览）。一笔转化的触点按时间排序，`touchpoint_order=1` 是最早的首触。

**Conversion (转化)。** 用户完成的一次有价值动作。注意数据集里引擎日聚合口径和 Floodlight 事件口径量级差很多，不能混用。

**Negative Keyword (否定关键词)。** 广告主主动排除、不让广告匹配的搜索词。本数据集不单独建否定关键词表，只通过搜索词记录里 `added_excluded = 'Excluded'` 体现历史排除事件。

**Broad-Match Overflow (广泛匹配溢出)。** 引擎服务了某条查询但匹配不回任何已存关键词，表现为搜索词记录的 `keyword_id` 为空。占比约 15%，过高说明匹配太松。

**Pacing (预算节奏)。** 实际日花费相对日预算的比例。超过 100% 是过投，远低于则可能预算受限或浪费。

**Budget Delivery (预算投放方式)。** Standard（全天平摊）或 Accelerated（尽快花完）两种预算消耗节奏。

**LTV (Lifetime Value，客户生命周期价值)。** 一个客户长期能带来的总价值，是广告主判断 CPC 出多高才划算的天花板。

**IAB (Interactive Advertising Bureau)。** 一个广告行业标准组织，本数据集的行业分类沿用它的风格（零售、旅游、金融等十类）。

**Engine (引擎)。** 投放广告的搜索平台，本数据集是 Google Ads 和 Microsoft Advertising 两家。

## 9. 关键指标与公式

下面把查询里会算到的指标用平白记法写出来。涉及金额或比率聚合时，分母为零要用 `NULLIF` 保护。

效率指标这一组是最常用的：

```
CTR             = clicks / impressions
avg CPC         = cost / clicks
conversion rate = conversions / clicks
CPA             = SUM(cost) / NULLIF(SUM(conversions), 0)
ROAS            = SUM(conversion_value) / NULLIF(SUM(cost), 0)
```

展示份额这一组描述拿到了多少机会、丢了多少、丢在哪：

```
impression_share + lost_is_budget + lost_is_rank ≈ 100
search_abs_top_is ≤ search_top_is ≤ impression_share
加权展示份额 = SUM(impression_share × impressions) / SUM(impressions)
```

最后这个加权写法很重要：展示份额是个按展示量加权的指标，跨天跨设备聚合时不能直接用 `AVG(impression_share)`，否则会把低量的桌面切片和高量的手机日同等对待。

预算节奏：

```
pacing %     = AVG(day_cost) / NULLIF(AVG(daily_budget), 0) × 100
monthly_budget = daily_budget × 30   (派生列, 恒等关系)
```

解析某天在效预算时，取 `effective_date ≤ report_date` 中最新的那一行，不要直接 join `campaign_budget`，否则一个 campaign 有多版预算会双重计数。

归因这一组是项目核心。每个触点在六种模型下的信用如下，每个模型下同一笔转化的信用加总都等于 1：

```
last_click_credit  = 1 给末触, 其余为 0
first_click_credit = 1 给首触, 其余为 0
linear_credit      = 1 / N        (N 为路径长度)
time_decay_credit  = 2^i / Σ 2^j  (越靠近转化权重越大)
position_credit    = 首末各 0.4, 中间平分 0.2; N=2 时退化为各 0.5
data_driven_credit = 归一化随机数 (模拟用, 非真实 DDA)
```

某渠道在某个归因模型下的价值，是该模型信用按转化金额加权求和：

```
渠道价值(模型) = SUM(该模型信用 × conversion_value)  按渠道分组
```

浪费治理和覆盖率这一组：

```
overflow %  = COUNT(keyword_id IS NULL) / COUNT(*) × 100   (按 ad group)
coverage %  = COUNT(有搜索词记录的关键词) / COUNT(Enabled 关键词) × 100   (按行业)
```

代理收入：

```
agency fee  = fee_percentage × 管理花费
```

最后留一个口径约定，避免下游 SQL 互相打架。前面已经说过，"转化数"在本数据集有两种来源：`daily_stats.conversions`（引擎日聚合，百万级）和 `conversion` 表（Floodlight 事件，5,000 行）。任何一个查询里只能选一种口径用到底，两者尺度不同，不可相加或逐行对比。涉及路径长度、归因信用、转化时延的分析用 `conversion` 表；涉及花费效率、CPA、ROAS 的报表用 `daily_stats`。
