# 第一部分:项目背景存档

## 1. 这个项目是什么,从哪来

### 1.1 母仓库

`ai_datafaker_pro` 这个仓库做的事是: **为各个垂直行业生成有业务含义的假数据集,每一个数据集讲一家虚构北美公司的数据故事。** 每套数据集配一份业务背景文档、一份 ER 文档、一套 SQL 查询、一个 Python 生成器,以及一批刻意植入的业务陷阱,供分析师去发现。

到本数据集为止,仓库里已经有二十多个数据集,覆盖 fintech、医疗、电商、游戏、广告、电信、公用事业等。**本数据集是其中之一,但它同时是一个更大项目的燃料** —— 这是它和其他数据集最重要的区别。

### 1.2 缘起:一段实习经历里的缺口

项目的起点是一位学生的实习经历: 纽约某量化机构的 Financial Analyst,在 Data 部门工作,负责的链路是 **数据清洗 → 搭建 portfolio 结构 → 构建协方差矩阵 → 由协方差推导权重分布 → 部分回测**。

我们先对这家机构做了公开调研,结论是: **它在公开互联网上几乎没有可核实的业务足迹** —— 无官网快照、无监管备案、无融资记录、无媒体报道、不在任何 2026 年量化机构榜单上,却在持续招实习生。综合判断更像一个 **实习经历供给方**,而不是一个可以拿来当业务原型的机构。所以项目 **剥离了这个品牌**,改以公开披露充分的行业头部机构 (AQR、Acadian、MSCI Barra 这一类) 作参照系,公司改为虚构的 **Tessellate Capital Management**。详细的核查过程见第 6 节。

**但学生口述里有真东西,而且被完整采纳了:**

| 口述细节 | 行业含义 | 在项目里的位置 |
|---------|---------|--------------|
| Research 与 Testing 部门组织上分离 | 不让建模的人给自己打分,是 model risk management 的核心原则 | **成为整个 AI Agent 设计的地基** (见 3.2) |
| 业绩指标由测试部门统一产出 | 公司有一条口径固定的评价流水线 | `factor_ic_monthly` + `factor_validation_run` 两张"裁判表" |
| covariance shrinkage 跨 regime 稳定风险估计 | T/N 不足时样本协方差必然奇异 | `covariance_estimate` 表与 T9 陷阱 |
| sector / liquidity / turnover / risk 四类约束 | 真实组合优化的标准约束集 | `constraint_set` 表与 T10 陷阱 |
| 交付物是四段式报告 | 机构研究备忘录的标准结构 | `agent_report_section` 的 section_type |

### 1.3 真正的缺口在哪里

把学生做过的事映射到系统化投研的完整链路上,一件事立刻浮出来:

```text
步骤 1  数据接入与 PIT 化        <- 他做过 (数据清洗)
步骤 2  因子构建                 <- 没碰到  |
步骤 3  单因子检验               <- 没碰到  |  这一段是缺口
步骤 4  因子组合与正交化          <- 没碰到  |
步骤 5  风险模型与协方差          <- 他做过
步骤 6  组合优化与约束            <- 他做过
步骤 7  回测、OOS 与归因          <- 他做过一部分
```

**"因子探索"(步骤 2 到 4)是他完全没碰到的一段,而它恰恰是整条链路里最耗人力、最重复、也最适合被 AI 接管的一段。**

一个真人研究员一周能认真检验 3 到 8 个假设,一个月 15 到 30 个,其中能活下来 1 到 3 个。**绝大部分时间花在"等回测跑完 → 发现结果不理想 → 再改一版"这个循环上。** 这不是智力密集,是耐心密集。

**项目就是从这个缺口长出来的。**

## 2. 我们最终要做的东西

### 2.1 一句话

**一个因子研究 AI Agent app。它没日没夜地挂在时间序列数据库上自主探索因子,人类只做两件事:批准,和验证。**

### 2.2 展开说

Agent 要做的是一个闭环,而且这个闭环必须能无人值守地一直转下去:

```text
经济直觉 / 文献 / 研究记忆
        |
   提出假设 (hypothesis)
        |
   把假设翻译成因子代码 / 业务查询
        |
   自主生成并执行复杂的 SQL —— 多层嵌套、聚合、组合、筛选
        |
   读结果, 判断: 有苗头就继续深挖, 不像样就换下一个
        |
   跑完整套体检 (IC / 分层 / 衰减 / 换手成本 / 正交性 / regime / 容量 / 多重检验)
        |
   自动整理成一份研究备忘录
        |
   成功与失败都写进研究记忆, 下一轮不再重复
```

**关键在"就继续深挖"和"就换下一个"这两个分支。** 一个只会把固定清单跑一遍的脚本不叫 Agent;**Agent 的价值在于它会根据看到的数字改变接下来要看什么。** 本数据集的 `agent_step` 表里,`decision` 字段的四个取值 (`continue` / `deepen` / `pivot` / `abandon`) 和 `decision_rationale` 字段,记录的就是这件事。

### 2.3 目标产能

| 单位 | 真人研究员 | Agent 目标 |
|------|-----------|-----------|
| 认真检验的假设数 | 一周 3-8 个 | **一小时 10 个以上** |
| 一个月的量 | 15-30 个假设,活 1-3 个 | **一小时跑完,收敛出 3-4 个** |
| 完整体检的深度 | 每个因子 10-12 种诊断 | **不能打折,必须同样是 10-12 种** |

**最后一行是硬约束。** "快"如果是靠少做检查换来的,那不叫提效,叫偷工。本数据集里被推进的 4 个假设,每个都跑满了 10 到 12 种不同的诊断 —— 和一个人类研究员该做的全套体检一样不少。

### 2.4 为什么是现在

因子研究的 Agent 化在 2025-2026 年已经从概念变成了一批可比较的框架: **AlphaAgent** (KDD 2025)、**XALPHA**、**FactorMiner**、**QuantaAlpha**、**AlphaMemo**、**AgonAlpha**、**QRAFTI**。它们共同确立了上面那个闭环范式,也共同识别出了它最大的三个敌人: **alpha 衰减、过拟合、以及 LLM 天然倾向于重新发明已有因子**。详见第 10 节。

值得单独记住的一个数字: AlphaAgent 报告的 **hit ratio 是 0.29**(相对无约束模型提升 81%)。**"探索 10 个方向,命中 3 个左右"** 不是我们拍脑袋定的,是有文献支撑的量级。本数据集把真实信号的数量就设成 4 个,正是照着这个来的。

## 3. 人机分工:为什么必须是"AI 探索 + 人类批准"

**这是整个项目最重要的一个设计判断,也是最容易被做错的地方。** 值得单独一节说清楚。

### 3.1 分工的形状

| | AI Agent | 人类 |
|---|---|---|
| **负责** | 广度 —— 穷尽所有的问法 | 判断 —— 这个方向值不值得上钱 |
| **动作** | 提假设、写查询、跑验证、写报告 | 读轨迹、批准或否决、承担后果 |
| **优势** | 不知疲倦、不怕重复、口径绝对一致 | 有先验、有责任、能问"这个数合不合理" |
| **上限** | 试得越多,假阳性越多 | 一周只能认真看 3-8 个假设 |

**两边的上限恰好互补,这就是分工能成立的原因。**

### 3.2 为什么不能让 AI 自己批准

四条理由,每一条在本数据集里都有对应的陷阱做实证:

**第一,多重检验。AI 最大的优势,正面撞上因子研究最大的陷阱。**

一个真人一周试 5 个假设,一个 Agent 一小时试 100 个。而按 5% 显著性水平,**试 200 个毫无意义的因子,平均会有 10 个"显著"** —— 纯粹靠运气。Harvey、Liu、Zhu 的结论很直接: 在因子动物园的语境下,继续用 t > 2.0 当门槛在统计上和经济上都说不通,新因子需要跨过 **t > 3.0**。

**一个只会"多试"的 Agent,产出的一定是垃圾。** 所以本数据集把 **尝试次数做成了一个会抬高显著性门槛的字段** (`agent_hypothesis.applied_t_threshold`),而不是留在文档的注意事项里。数据集里的 `SEARCH_TREND` 就是这条规则的实证: t = 2.32,过得了传统的 2.0,过不了第 8 次尝试对应的 3.36。

**第二,PIT 纪律。错误的口径会给出一个"显著且强大"的假因子。**

数据集里的 `PEAD_SUE`: join 条件从 `publish_date` 换成 `fiscal_period_end`,RankIC 从 0.0273 虚增到 0.1096,**4.02 倍**。而两种口径的 t 值分别是 3.79 和 4.23 —— **都远超任何门槛**。也就是说,**显著性检验完全无法识别 look-ahead bias。**

能救你的只有对数字量级的业务直觉。数据集里 Atlas 之所以去查 PIT 口径,是因为它在决策日志里写下了: *"对一个众所周知的公开异象来说,第一遍的 IC 高得不合理。"* —— **这种"太好了所以可疑"的直觉,目前仍然需要人来兜底。**

**第三,成本与容量。纸面 alpha 和能落到客户账户上的 alpha,差着一半。**

数据集里的三个数字: `STR_REV_5D` 毛 IR 1.67 → 净 IR 0.83 (换手 22.8 倍吃掉一半);`MICRO_VALUE` 全池 IC 0.0317 看着很强,但效果全在最小的 250 只票上,容量只有 2.14 亿美元;复合信号无约束净 IR 1.32,套上完整生产授权后只剩 0.61 (**削掉 53.8%**)。

**这些约束不来自数据,来自机构的现实 —— 管多少钱、客户签了什么条款、交易台能吃下多大的量。Agent 没有这些上下文,人有。**

**第四,也是最重要的一条: 标准验证流水线有盲区,而盲区只能靠"换个问法再问一遍"发现。**

数据集里的 `FCF_MARGIN_TTM` 是这条的完整演示: 它在验证流水线里拿到 **PASS** —— t = 6.39、净 IR 2.63、与存量因子相关性只有 0.19、容量 76 亿美元、IC 胜率 83.3%,**7 条判定规则一条都没触碰**。但用 `version = 1` 的原始财报重算,RankIC 从 0.0296 掉到 **0.0071**。

**为什么流水线抓不到它: 污染发生在数据层,而验证发生在指标层。** 无论你把 t 门槛提到多高,都救不了输入本身是错的。

**而这恰恰是 Agent 最该干的活。** 把一整套回测在四种数据口径下各重跑一遍,对人是几天的工作量,对 Agent 是几分钟。**AI 的价值不只是快,是它能穷尽人不愿意穷尽的问法。**

### 3.3 三道闸

基于上面四条,app 必须有三道人类守得住的闸:

1. **独立的验证流水线,Agent 无权改写。** 对应数据集里的 `factor_ic_monthly` 与 `factor_validation_run` —— 口径固定,由"验证组"产出,研究员和 Agent 都改不了。这是从学生口述里那个"Research 与 Testing 分离"直接搬过来的制度设计。
2. **尝试次数计入门槛,自动生效。** 对应 `applied_t_threshold`。而且真实系统里分母还要更大 —— 研究部门在同一份数据上 **历史累计** 试过的次数,才是真正的分母。
3. **人类终审,看的是轨迹不是结论。** 这一条决定了 app 的界面长什么样,见 3.4。

### 3.4 人类批准时到底在看什么

**不是看"Agent 说这个因子好"。** 是看:

- **假设是从哪来的** (`idea_source`: 文献 / 记忆 / 数据挖掘 / 分析师笔记) —— 数据挖掘来的先验最弱,要额外警惕
- **它跑了多少 *种* 诊断** (`COUNT(DISTINCT step_type)`) —— 而不是多少 *步*。把同一种检验跑 20 遍,步数很好看,诊断种类会暴露它
- **每一次"深挖"和"放弃"背后的数字与理由** (`decision` + `decision_rationale` + `key_metric_value`)
- **预算是怎么分配的** —— 被推进的假设是不是拿到了更多的步数和成本
- **否决理由能不能复现** —— 每条否决都要能追溯到一个具体的、可以自己跑一遍的查询

本数据集的 `agent_run` / `agent_hypothesis` / `agent_step` / `agent_finding` / `agent_report_section` 这五张表,存在的全部理由就是支撑这个审批界面。**它们记录的不是"因子研究的结果",而是"因子研究的过程"。**

## 4. 数据集在整个项目里的位置

### 4.1 三重角色

**角色一: 冷启动燃料。** app 要跑起来,需要一个足够大、足够复杂的时间序列数据库让 Agent 去探索。本数据集提供了 29 张表、约 194.5 万行、899 个交易日、1,200 只美股 (含 120 只已退市) 加 40 个跨资产代理。

**角色二: 回归测试基准 —— 这是最重要的一重。**

真实市场数据有一个致命问题: **没有人知道正确答案。** 一个 Agent 说它找到了一个因子,你无法判断它是对的还是在过拟合,只能等几年看实盘。

**合成数据没有这个问题。我们知道每一条陷阱的确切量级。** 于是本数据集可以当作一把尺子,客观地给任何一版 Agent 打分:

| 评测项 | 标准答案 |
|--------|---------|
| 该推进几个假设 | **4 个** (ACC_QUALITY / EPS_REV_60D / PEAD_SUE / STR_REV_5D) |
| 该否决几个 | **6 个** |
| 每个否决的理由 | 伪新因子 / 容量陷阱 / regime 依赖 / 多重检验 / 幸存者偏差 / 财报修订 |
| 有没有发现 look-ahead | IC 该从 0.1096 掉回 0.0273 |
| 有没有发现修订污染 | `FCF_MARGIN_TTM` 该被否决,**尽管标准流水线给它 PASS** |

**最后一行是最狠的一道题。** 一个 Agent 如果只会读验证表,它一定会把 `FCF_MARGIN_TTM` 推进去 —— 因为所有常规指标都完美。**只有主动改写数据口径重算的 Agent 才能过这一关。这道题直接区分"会查表的 Agent"和"会做研究的 Agent"。**

**角色三: 教学材料与 few-shot 素材。** 22 条 SQL 查询就是 Agent 该会写的那类查询;`agent_step.sql_text` 里存的 84 条查询可以直接当 few-shot 示例,也可以拿来做回归测试。

### 4.2 为什么必须先做合成数据

一句话: **因为要先有尺子,才能量东西。**

直接拿真实数据做 Agent,你会陷入一个死循环 —— Agent 产出一堆结论,你无法验证,只能靠人工逐条复核,而人工复核的产能恰恰是这个项目要绕开的瓶颈。**先用一份知道答案的数据把 Agent 调对,再换真实数据,是唯一能收敛的路径。**

### 4.3 路线图

| 阶段 | 内容 | 状态 |
|------|------|------|
| **一** | 合成数据集: 29 张表、10 个假设、10 条陷阱、22 条 SQL | **已完成** |
| **二** | Agent 原型: 跑通自主探索闭环,在本数据集上达到"推进 4 个、否决 6 个且理由正确" | 待做 |
| **三** | app: 人机协作界面 —— 审批队列、轨迹回放、独立验证流水线、研究记忆 | 待做 |
| **四** | 接真实市场数据,人类审批比例逐步下调 | 待做 |

**阶段二的验收标准就是 4.1 那张表。** 这也是为什么数据集必须把 `agent_*` 五张表做出来 —— 它们既是"标准答案"的载体,也是 app 界面的数据契约。

这份文件是 **项目备忘**,不是数据集的业务文件:

- **不是** 评审流水线 (`review-fake-data-generator`) 的审查对象

# 第二部分:行业调研

> 以下是支撑上述项目设计的行业事实。这部分回答的是"真实机构到底怎么做因子研究",以及"这件事的 AI Agent 化在 2025-2026 走到了哪一步"。

## 5. 行业调研结论摘要

1. **原型机构不可用。** 学生实习所在的 DeepManifold Inc 在公开互联网上几乎没有可核实的业务足迹 —— 无官网快照、无监管备案、无融资记录、无媒体报道、不在任何 2026 年量化机构榜单上。结合"项目制运作 + 大量实习生 + title 与实际工作错位"的特征,它更像一个 **实习经历供给方**,而不是一个可以拿来当业务原型的机构。**本项目剥离该品牌,改用虚构公司。**
2. **参照系改为行业头部。** 真正值得参照的是公开披露充分的系统化资管机构 —— AQR、Acadian、MSCI Barra、Axioma 这一类。它们的投研流程、因子体系、风险模型、评价口径都有公开材料可查,足以支撑一个可信的虚构公司。
3. **因子研究的 AI Agent 化不是想象,是 2025-2026 的现实前沿。** 学术界已经有一批成型框架:AlphaAgent(KDD 2025)、XALPHA、FactorMiner、QuantaAlpha、AlphaMemo、AgonAlpha、QRAFTI。它们共同确立了一套 **"假设 → 代码 → 回测 → 反馈 → 记忆"** 的闭环范式,并且已经识别出这个范式最大的敌人:**alpha decay(因子衰减)、过拟合、以及 LLM 天然倾向于重新发明已有因子**。这些恰好是我们数据集要植入的陷阱。
4. **一个真人研究员的产能基线是可量化的。** 一周认真检验 3-8 个假设,一个月 15-30 个,其中能活下来 1-3 个。这就是"AI 一小时顶一个月"这句话需要跨过的具体门槛 —— 也是我们 use case 的定量目标。

## 6. 关于原型机构的核查(为什么剥离品牌)

### 6.1 检索过程与结果

本次调研对 DeepManifold Inc 执行了六个方向的检索:

| 检索方向 | 结果 |
|---------|------|
| 公司通用(名称 + 量化 + 纽约) | 无实质信息;返回的是 Manifold Trading、Manifold Partners、Deep Nexus 等同名或近名的其他公司 |

### 6.2 从学生口述里仍然可用的部分

品牌剥离,不代表口述信息作废。口述里有一批 **结构性事实** 依然是好的设计输入,因为它们本身就是行业通行做法:

| 口述细节 | 行业含义 | 是否采纳进项目 |
|---------|---------|--------------|
| Research 与 Testing(测试部门)组织上分离 | 这是 model risk management 的核心原则:不让建模的人给自己打分 | **采纳,且是核心机制** |
| 业绩指标(IR ~1.4)由测试部门统一产出 | 说明公司有一条标准化评价流水线,口径统一 | **采纳** |
| 多资产风险分析框架 | multi-asset,不是单一股票池 | **采纳** |
| covariance shrinkage 用于跨 regime 稳定风险估计 | 样本协方差在 N 接近 T 时病态,必须收缩 | **采纳** |
| 组合带 sector / liquidity / turnover / risk 四类约束 | 真实组合优化的标准约束集 | **采纳** |
| 交付物是四段式报告(假设、风险驱动、局限、验证结论) | 机构研究报告的标准结构 | **采纳,作为 Agent 报告模板** |

### 6.3 一个附带的判断

一家在纽约做量化、公开网络上近乎隐形、却持续招实习生的机构,通常落在这几类里:自营机构(不募资所以无备案)、B2B 研究供应商(靠转介绍获客)、或者 **以实习生为主要人力来源的项目制作坊**。前两类是正常商业形态,第三类对学生的简历价值有限 —— 因为招聘方无法核实,而项目本身也很难说清楚。

这正好反过来说明了我们这个数据集项目的价值:**给学生一个业务逻辑经得起追问、技术难度真实、且能拿出可运行成果的项目**,比一段无法核实的实习更有说服力。

## 7. 参照系:行业头部机构怎么做系统化投资

**【公开可核实】** 以下内容来自各机构的公开研究材料与方法论文档。

### 7.1 AQR:研究驱动的系统化平台

AQR 的系统化股票平台强调"通过持续研究与创新演进",公开材料明确提到把 **机器学习、自然语言处理、另类数据** 用于持续增强三个环节:**信号(signals)、组合构建(portfolio construction)、交易执行(trading implementation)**。

值得注意的是它对研究流程的描述:一个现代实证金融的工作流,是"基于经济直觉生成信号与因子组合,在跨越数十年、覆盖广泛横截面的大型面板数据上评估它们,并进行稳健性检验";并且明确承认这个过程 **"数据密集,且对实现细节高度敏感 —— universe 筛选、滞后约定(lag conventions)、分组断点定义、加权规则"**。

> **对我们的启示:** 同一个因子,换一个 lag 约定或者换一个断点定义,结果可以完全不同。这意味着我们的数据集里,**"口径"本身必须是一个可被查询、可被比较的维度**,而不是一个隐含假设。

### 7.2 Acadian:百人级的因子库工程

Acadian 的公开材料给出了另一个关键量级:**超过 100 人** 在持续"review、evolve、hone、refine、fine tune"模型,以从公开市场中提取彼此不相关的 alpha 信号。

它的因子组织方式是分层的:**单个 signal → 聚合成 factor → 归入宽泛的主题(theme)**。在股票上,主题分为四组:**Value(相对估值)、Growth(盈利动态与前瞻预期)、Quality(资产负债表强度与运营效率)、Technical(价格与交易趋势)**;在信用上,主题映射为 **Value、Carry、Momentum**。

它的归因工具能把收益驱动分解为 **alpha 信号敞口** 与 **风险因子敞口** 两部分,后者包括 sector、ratings、size、maturity、duration、region。

> **对我们的启示:** 三层结构(signal → factor → theme)是数据模型的直接输入。归因必须区分"alpha 贡献"与"风险因子贡献" —— 一个看起来赚钱的因子,收益可能全部来自它偷偷承担的 size 或 duration 敞口。

### 7.3 MSCI Barra / Axioma:风险模型的工业标准

Barra 的美股模型(USE3)覆盖 **67 个因子:54 个行业因子 + 13 个风格因子**(含 momentum、growth、size 等)。

风险模型的数学核心是把协方差矩阵分解为:

```
Σ = β · Σ_f · β' + Σ_idio
```

其中 `β` 是资产在因子上的暴露矩阵,`Σ_f` 是因子收益的协方差矩阵,`Σ_idio` 是对角的特异性风险矩阵。

因子相关矩阵用 **指数加权平均(EWMA)** 从日频因子收益算出,给近期观测更大权重以应对非平稳性。关键约束是:**半衰期必须足够长,使有效观测数 T 显著大于因子数 K**,否则相关矩阵病态。

另有研究指出:**"收缩后的样本协方差矩阵,本质上就是一个特殊形式的因子模型"** —— 把若干风格因子与主成分组合起来,配一个(块)对角的因子协方差。这一点解释了为什么 shrinkage 和因子模型在实践中经常被当成同一件事的两种说法。

> **对我们的启示:** 学生实习里最难的那一环(协方差理论选择 + 如何用它推导权重),在行业里有清晰的标准答案框架。数据集应该让 T/N 比、半衰期、收缩强度这几个参数 **可查询、可对比**,让 Agent 能真正做出"这个协方差估计在这个 regime 下不可靠"的判断。

### 7.4 学术界的红线:因子动物园与 t > 3.0

Harvey、Liu、Zhu 的《…and the Cross-Section of Expected Returns》(RFS, 2016)是这个领域最重要的方法论警告。核心论点:

- 已有数百篇论文、数百个因子声称能解释横截面收益,这构成了大规模的数据挖掘。
- 在这种前提下,**继续用 t > 2.0 作为显著性门槛,在经济上和统计上都说不通**。
- 论文给出了一个考虑了检验间相关性与发表偏差的多重检验框架,并给出从 1967 年至今的历史显著性阈值时间序列。
- **结论:一个新因子需要跨过 t > 3.0 的门槛**,而且"金融经济学里大部分声称的研究发现很可能是假的"。

配套的另一条红线来自 Bailey 与 López de Prado 的 **Deflated Sharpe Ratio(DSR)**:一个报告出来的 Sharpe ratio,必须按 **尝试次数、偏度、峰度** 三个维度打折。他们从数学上证明了 —— **只要试的策略配置足够多,高的模拟业绩几乎必然出现**;而且金融序列的记忆效应会让过拟合的策略在样本外系统性地跑输。选到一个过拟合策略的概率,随尝试次数快速上升。

> **对我们的启示,也是本项目最关键的一条:**
> **AI Agent 的最大优势(一小时试一百个假设)恰恰是它最大的风险(多重检验爆炸)。** 一个只会"多试"的 Agent,产出的一定是垃圾。所以我们的 Agent 设计里,**必须显式建模尝试次数,并让评价门槛随尝试次数上升**。这既是真实的行业约束,也是整个数据集最有教学价值的一课。

## 8. 端到端投研流程:七步

**【行业重构,基于第 7 节的公开材料】** 每一步注明:做什么 / 产出什么 / 最常见的坑。

### 步骤 1. 数据接入与 PIT 化

- **做什么:** 落库行情、财务、分析师预期、宏观、另类数据;做复权、货币换算、时区与交易日历对齐;给每条记录打上 **as-of 时间戳**。
- **产出:** 一个 point-in-time (PIT) 数据库 —— 问"2024-03-15 那天我能看到什么",只返回那天之前已发布的数据。
- **最常见的坑:** **look-ahead bias。** 财报的 `fiscal_period_end` 是 2024-03-31,但 `publish_date` 是 2024-05-08。因子若在 4 月就用上这份财报,回测凭空多出两个月的先知优势,IC 虚高得离谱。

### 步骤 2. 因子构建

- **做什么:** 把原始数据变成"每个资产、每个交易日一个打分"的横截面。
- **产出:** `factor_value(factor_id, asset_id, trade_date, raw_value, z_score, rank_pct)` 这样的长表。
- **最常见的坑:** **口径不一致。** 同一个"12 个月动量",跳过最近 1 个月(经典 12-1)和不跳,IC 能差一倍。AQR 公开材料里点名的 lag conventions、breakpoint definitions、weighting rules,说的就是这件事。

### 步骤 3. 单因子检验

- **做什么:** 对每个因子跑一整套标准检验(见第 9.3 节的指标表)。
- **产出:** 一份因子体检报告 + 一个"通过 / 有条件通过 / 不通过"的结论。
- **最常见的坑:** **多重检验。** 试 200 个因子,按 5% 显著性水平,平均会有 10 个纯靠运气"显著"。不做校正,因子库就会塞满噪声。

### 步骤 4. 因子组合与正交化

- **做什么:** 把通过检验的因子合成复合信号;先对已知风格因子(市值、行业、Beta)做 **中性化**,再做因子间正交化。
- **产出:** composite alpha score。
- **最常见的坑:** **伪新因子。** 一个"新"因子跟已有低波动因子相关性 0.85,它带来的不是新 alpha,是同一个 beta 换了个名字。单因子 IC 看着很棒,加进组合后增量为零。

### 步骤 5. 风险模型与协方差矩阵

- **做什么:** 按 `Σ = β Σ_f β' + Σ_idio` 估计协方差;用 EWMA 处理非平稳;用 shrinkage(Ledoit-Wolf、OAS)处理 T/N 比不足导致的病态。
- **产出:** 稳定、可求逆的 Σ,以及由它推导的风险预算。
- **最常见的坑:** **回看窗口与 regime 不匹配。** 用 250 天窗口估的 Σ,在市场刚进入高波动 regime 的头两周会严重低估风险,优化器于是给出过度集中的权重。

### 步骤 6. 组合优化与约束

- **做什么:** 求解 `max wᵀα − λ·wᵀΣw − TC(w, w_prev)`,约束包括 sector 敞口上下限、单资产权重上限、流动性约束(占单日成交额比例)、换手上限、tracking error 上限。
- **产出:** 目标权重向量与调仓单。
- **最常见的坑:** **约束把 alpha 削光。** 无约束下 IR 1.8 的信号,加上 sector 中性 + 换手上限 20% 后可能只剩 IR 0.6。所以约束前后必须同时呈现。

### 步骤 7. 回测、OOS 与归因

- **做什么:** **Walk-forward out-of-sample** —— 滚动窗口训练,只在窗口之后一段做预测,再往前滚。加交易成本模型(佣金 + 价差 + 冲击成本)。然后做三类归因:收益归因、风险贡献分解(risk contribution decomposition)、回撤归因(drawdown attribution)。
- **产出:** 净值曲线、IR、MaxDD、换手、成本后收益、归因表、**Deflated Sharpe Ratio**。
- **最常见的坑:** **样本内 / 样本外落差。** 样本内 IR 2.0、OOS IR 0.3 是最典型的过拟合信号。健康的因子应当在 OOS 保留至少一半左右的效果。

## 9. 数据与因子研究方式(细节层)

### 9.1 PIT 数据与三类偏差

| 偏差 | 机制 | 后果 | 数据层怎么防 |
|------|------|------|------------|
| **Look-ahead bias** | 用了当时还没公布的数据 | IC 虚高,OOS 崩盘 | 每条记录带 `publish_date` / `as_of_date`,查询强制按 as-of 过滤 |
| **Survivorship bias** | 资产池只含今天还存在的标的,退市/被并购的被剔除 | 收益系统性高估(死掉的都是差的) | 资产表保留 `delisted_date`,universe 按历史时点重建 |
| **Restatement bias** | 财报事后被修订,库里只留最新版 | 用到了"修订后"的数字,而当时看到的是原始版 | 财务表保留 `version` 与 `restated_flag`,同一 `fiscal_period` 允许多版本 |

### 9.2 因子分类学

参照 Acadian 的三层结构(signal → factor → theme):

| 主题 Theme | 直觉 | 代表构造 | 典型换手 |
|-----------|------|---------|---------|
| **Value** | 便宜的资产长期跑赢 | E/P、B/P、FCF Yield、EV/EBITDA | 低 |
| **Growth** | 盈利动态与前瞻预期 | 营收增速、EPS 修正方向、SUE | 中 |
| **Quality** | 好公司更抗跌 | ROE、毛利率稳定性、应计项、杠杆 | 低 |
| **Momentum** | 涨的继续涨 | 12-1 动量、时序动量、行业动量 | 中高 |
| **Technical** | 价格与交易行为 | 反转、换手率、量价背离 | 高 |
| **Low Volatility** | 低波资产风险调整后更优 | 已实现波动率、Beta、下行波动 | 低 |
| **Liquidity** | 流动性差要溢价补偿 | Amihud 非流动性、成交额、价差 | 中 |
| **Carry** | 跨资产的持有收益 | 期限利差、信用利差、展期收益 | 低 |
| **Sentiment / Alt Data** | 传统数据外的信息 | 新闻情绪、分析师修正、网页流量、招聘数据 | 中高 |

### 9.3 因子评价指标定义表

这张表是数据集 SQL 查询的核心口径来源,也是 AI Agent 的"评分卡"。

| 指标 | 定义 | 及格线量级 | 说明 |
|------|------|-----------|------|
| **RankIC** | 每个截面上,因子排名与下期收益排名的 Spearman 相关系数 | 单期 \|IC\| > 0.02 已可用 | 用排名而非原值,抗极端值 |
| **IC Mean** | RankIC 的时序均值 | > 0.02 | 因子的平均预测力 |
| **IC Std** | RankIC 的时序标准差 | 越小越好 | 稳定性 |
| **ICIR** | IC Mean / IC Std | > 0.3 可用,> 0.5 好 | 因子研究里最重要的单一指标 |
| **IC t-stat** | IC Mean / (IC Std / √N) | **单因子 > 2.0;因子动物园语境下应提高到 > 3.0** | Harvey-Liu-Zhu 的核心结论 |
| **IC 胜率** | RankIC > 0 的期数占比 | > 55% | 稳定性的直观版本 |
| **分层单调性** | 按因子分 5-10 层,各层下期收益是否单调 | 单调 + 首末层差显著 | 非单调说明关系非线性或伪 |
| **多空价差 (Q5−Q1)** | 最高层减最低层的年化收益 | > 3% | 因子的"毛收益" |
| **半衰期 (decay)** | IC 随预测期延长衰减到一半所需天数 | 越长越好 | 决定调仓频率与容量 |
| **换手率 (turnover)** | 每期权重变化绝对值之和的一半 | 与成本直接挂钩 | 高换手因子成本后常归零 |
| **成本后 IR** | 扣掉佣金、价差、冲击成本后的信息比率 | > 0.5 才值得上线 | **唯一真正重要的指标** |
| **Deflated Sharpe Ratio** | 按尝试次数、偏度、峰度打折后的 Sharpe | > 0 且显著 | 对抗"试得多必有好看的" |
| **Tracking Error** | 组合相对基准收益的年化标准差 | 3%-6% 常见 | 约束条件 |
| **MaxDD** | 最大回撤 | 越小越好 | 客户最敏感的数字 |
| **与已有因子相关性** | 新因子 IC 序列与老因子 IC 序列的相关系数 | < 0.5 才算新 | 防"伪新因子" |
| **容量 (capacity)** | 不显著侵蚀 alpha 前提下能承载的资金规模 | 与流动性、换手挂钩 | 小市值上有效不代表能上规模 |

### 9.4 因子研究的八种失败模式

**这一节是全文对数据集设计最有价值的部分 —— 每一种失败模式都可以做成数据里的一个陷阱,让 AI Agent 去踩、去识别、去排除。**

| # | 失败模式 | 表面现象 | 真相 | 怎么在数据里做出来 |
|---|---------|---------|------|------------------|
| 1 | **Look-ahead** | IC 高得不真实(0.15+) | 用了未发布数据 | 财务表 `publish_date` 显著晚于 `period_end`,不按 as-of 过滤就穿越 |
| 2 | **幸存者偏差** | 多头组收益漂亮 | 退市标的被剔除 | 资产表含已退市标的,退市前收益极差 |
| 3 | **多重检验** | 10 个方向里 2 个 t > 2 | 纯属运气 | 多数因子真实 IC 设为 0,靠噪声制造偶发显著 |
| 4 | **成本吞噬** | 毛收益 8%,IR 1.5 | 换手 400%,成本后归零 | 高换手因子 + 真实的价差与冲击成本模型 |
| 5 | **Regime 依赖** | 全样本 IC 0.04 | 只在低波 regime 有效,高波时反向 | 数据里植入 regime 标记,因子效果按 regime 反转 |
| 6 | **伪新因子** | 单因子 ICIR 0.6 | 与已有低波因子相关性 0.85 | 新因子构造成老因子的线性变换 + 少量噪声 |
| 7 | **容量陷阱** | 全池 IC 0.05 | 效果全部来自最小 20% 市值 | 因子效果与市值分层强相关,大市值段 IC 接近 0 |
| 8 | **数据修订** | 历史回测稳定 | 用的是修订后财报 | 财务表保留多版本,原始版与修订版差异显著 |

### 10.1 已成型的框架

| 框架 | 出处 | 核心贡献 |
|------|------|---------|
| **AlphaAgent** | KDD 2025 | LLM 多智能体挖掘 **抗衰减(decay-resistant)** 因子,靠三重正则化约束探索 |
| **XALPHA** | 2026 | 把"研报吸收 → 记忆引导的假设规划 → 代码化因子演化 → 实证验证 → 发现反馈固化"组织成统一的 hypothesis-to-code 研究闭环 |
| **FactorMiner** | 2026,清华 + 鹏城实验室 | LLM 因子生成 + **结构化经验记忆**,自演化 |
| **QuantaAlpha** | 2026 | 演化式(evolutionary)框架驱动 LLM 挖因子 |
| **AlphaMemo** | 2026 | 把 **搜索过程本身** 结构化存进记忆,供后续迭代复用 |
| **AgonAlpha** | 2026 | prompt economy + 可扩展的 agentic search |
| **QRAFTI** | 2026 | 面向量化金融实证研究的通用 agentic 框架 |

### 10.2 这批工作的共识范式

把它们的共同点抽出来,就是我们 Agent 的流程骨架:

```
经济直觉 / 研报 / 记忆
        ↓
   假设生成 (hypothesis)
        ↓
   因子代码化 (hypothesis → code)
        ↓
   实证验证 (IC / ICIR / 分层 / 回测)
        ↓
   反馈与筛选 (继续深挖 or 放弃)
        ↓
   经验固化进记忆 (成功与失败都记)
```

关键在最后一步:**失败也要记**。否则 Agent 会在第 40 个假设时重新发明第 7 个假设。

### 10.3 AlphaAgent 的三重正则化(最值得抄的设计)

AlphaAgent 明确指出,不加约束的 LLM 挖因子会退化成"换皮的已有因子 + 越来越复杂的表达式"。它的解法是三条正则:

1. **复杂度控制(complexity control):** 限制符号长度、参数个数、使用的特征数量。防止 Agent 靠堆表达式过拟合。
2. **原创性强制(originality enforcement):** 用 **AST 结构相似度** 对比已有因子库,拒绝实质重复的因子。
3. **假设-因子对齐(hypothesis-factor alignment):** 用 LLM 做语义一致性检查 —— 你说的假设,和你写出来的因子,是不是同一件事。

它报告的效果:年化超额 11.00%(CSI 500)/ 8.74%(S&P 500),IR 1.488(CSI 500),同时 MaxDD 最低;**hit ratio 0.29(相对无约束模型提升 81%)**,开发成功率 0.83。最关键的一点是:**它产出的因子在五年里 IC / RankIC 保持稳定,而传统因子显著衰减到接近零。**

> **对我们的启示:** "hit ratio 0.29" 是个极好的锚 —— **AI Agent 探索 10 个方向,命中 3 个左右**,这与用户设定的"10 个方向收敛到 3-4 个"完全吻合,而且有文献支撑。我们的数据集应该把真实信号的数量就设成 3-4 个。

### 10.4 Agent 化真正的风险

结合第 7.4 节的 Harvey-Liu-Zhu 与 Bailey-López de Prado:

| 风险 | 为什么 Agent 让它更严重 | 数据集要提供的解药 |
|------|---------------------|------------------|
| **多重检验爆炸** | 人一周试 5 个,Agent 一小时试 100 个 | 记录 `trial_count`,让显著性门槛随尝试次数上升;提供 Deflated Sharpe Ratio |
| **重新发明轮子** | LLM 训练语料里全是经典因子,它会自然"想到"动量 | 提供已有因子库 + 相关性检验,让"伪新因子"能被识别 |
| **表达式膨胀过拟合** | LLM 很擅长把式子写复杂 | 记录因子的复杂度指标(操作符数、特征数),把复杂度纳入评价 |
| **只看毛收益** | 回测框架默认不含成本 | 数据集必须自带价差、成交额、冲击成本参数,让成本后 IR 可算 |
| **无法解释** | 客户不买"黑箱说它行" | Agent 报告必须含四段式:假设、风险驱动、局限、验证结论 |

## 11. Analyst / Quant 的日常与产能基线

### 11.1 一天

| 时间 | 事情 |
|------|------|
| 8:00-9:00 | 看隔夜数据管线:有没有缺失、异常值告警、数据源延迟 |
| 9:00-9:30 | 站会。研究员说昨天试了什么、今天要试什么;验证组说哪几个因子跑完了 |
| 9:30-12:00 | 写代码:构造一个新因子,或改一版协方差估计,或修回测里的 bug |
| 13:00-16:00 | 跑实验、看结果。**绝大部分时间在等回测跑完,然后发现结果不理想,再改一版** |
| 16:00-18:00 | 整理结论、写文档;把值得提交的因子定义打包交给验证组 |

### 11.2 产能基线(本项目的定量目标)

| 单位 | 认真检验的假设数 | 存活数 |
|------|---------------|-------|
| 一周 | 3-8 个 | 0-1 |
| 一个月 | 15-30 个 | 1-3 |
| 一个 4-6 周的项目 | 10-30 个候选 | 3-5 个入围 |

> **这就是"一个 analyst 一个月"的真实产能。我们的 AI Agent 要在一小时内复现的,正是这个数量级 —— 探索 10 个方向,收敛出 3-4 个。**

### 11.3 一个项目周期(4-6 周)

| 周 | 阶段 | 产出 |
|----|------|------|
| W1 | 立项与数据摸底 | 数据可用性报告、universe 定义 |
| W2-W3 | 因子探索 | 研究日志,10-30 个候选假设 |
| W4 | 筛选与组合 | 3-5 个入围因子,复合信号 |
| W5 | 风险模型与组合构建 | 协方差、约束、目标权重 |
| W6 | 验证与交付 | Walk-forward OOS 结果、归因、最终报告 |

### 11.4 产出物清单

1. **研究日志(research log)** —— 每个假设一条,含动机、构造、结果、结论。**失败的也要记**,否则半年后有人重试同一个死胡同。
2. **因子体检报告** —— 第 9.3 节那张指标表,每个因子一份。
3. **组合构建说明** —— 约束设置、优化器参数、权重分布。
4. **独立验证报告** —— 验证组出的结论,研究员不能自己改。
5. **给 stakeholder 的分析摘要** —— 四段式:model assumptions、key risk drivers、limitations、validation results。

## 14. 对数据集设计的十二条要求

1. **时间序列是主干。** 核心事实表是 `(asset_id, trade_date)` 日频粒度,行数量级到百万级,才撑得起真实的因子检验统计量。
2. **必须是 PIT 的。** 财务、分析师、宏观数据都带 `publish_date` / `as_of_date`,让 look-ahead 成为一个 **真实可犯的错误**。
3. **必须多资产。** 至少覆盖股票 + 跨资产 sleeve(ETF / 期货代理),呼应 multi-asset 定位。
4. **必须含已退市资产。** 幸存者偏差要能被实际观测到,而不只是文档里的一句提醒。
5. **要有 regime 标签。** 让"因子只在某个 regime 有效"这个陷阱能被验证。
6. **要有完整的成本要素。** 价差、成交额、冲击成本参数,让"成本后 IR"能被真实计算。
7. **因子库预置约 10 个候选方向**,其中 **3-4 个是真信号**(与 AlphaAgent 的 hit ratio 0.29 吻合),其余各自对应第 9.4 节的一种失败模式。
8. **要有独立验证流水线表。** 存储验证组口径下的 RankIC、ICIR、分层收益、DSR,作为 Agent 无法自我操纵的裁判。
9. **要有 Agent 探索轨迹表。** 记录假设、生成的查询、结果、继续深挖还是放弃的决策、累计尝试次数 —— **这是本数据集区别于普通量化数据集的关键**,也是"AI agent app"能直接消费的部分。
10. **要有组合构建与约束表。** 协方差元数据(窗口、半衰期、T/N 比、收缩强度)、约束设置、约束前后的权重与业绩对比。
11. **SQL 查询分两层。** 约一半是支撑性 query(日收益、横截面 z-score、RankIC、换手、成本),另一半是分析性 query(因子筛选、regime 切分、相关性去重、成本后排序、多重检验校正、最终 3-4 个方向的论证)。
12. **叙事重心是 AI Agent。** 业务文档要讲清楚:为什么研究产能就是这家公司的产能;Agent 怎么从 10 个方向收敛到 3-4 个;它凭什么可以被信任(独立验证 + 尝试次数校正 + 四段式报告)。
