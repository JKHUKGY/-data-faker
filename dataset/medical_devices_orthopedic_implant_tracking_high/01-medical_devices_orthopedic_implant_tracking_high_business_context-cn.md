# 医疗器械: 骨科植入物追踪业务背景

> 本文档是这个数据集的业务总纲。它解释公司是谁, 靠什么挣钱, 所处行业怎么运作, 这套数据库要回答哪些问题, 以及读懂数据所需的全部行业术语。数据结构本身 (表, 字段, 生成规则, 业务陷阱) 请见 `02-medical_devices_orthopedic_implant_tracking_high_er_document-cn.md`; 具体 SQL 练习见 `03-medical_devices_orthopedic_implant_tracking_high_sql_queries-cn.md`。

读这份文档的人, 设想成刚加入项目的新分析师。读完它, 你应该能在第一次站会上跟同事讨论 "Class I 召回的通知 SLA" 或者 "consignment 库存为什么不计入资金占用", 而不会一脸茫然。

## 1. 公司速写

**MAOHN (MidAtlantic Orthopedic Health Network, 米德大西洋骨科医疗网络)** 是一家虚构的非营利性区域医院集团, 总部位于美国大西洋中部地区 (Mid-Atlantic, 大致是 Maryland, Virginia, Pennsylvania 一带)。集团旗下经营 **12 家急性病医院 (acute care hospital)**, 单家床位规模从 50 张的社区医院到 800 张的区域级中心不等。

MAOHN 每年完成约 **6,000 例骨科手术**, 其中大约三分之二会用到至少一件植入器械, 包括全髋和全膝关节置换, 骨折内固定 (钢板, 骨钉, 髓内钉), 以及脊柱融合。这是一家以骨科见长的医院集团: 它没有自己造器械, 而是把全国主要厂商的植入物买进来, 装进病人体内, 然后对这些器械负终身追溯责任。

公司高管层在本数据集里会被反复点名, 因为很多查询就是替他们准备的:

- **CFO (首席财务官)** 盯成本, 尤其是植入器械的单例成本。
- **CMO (Chief Medical Officer, 首席医疗官)** 对临床安全和召回响应负责。
- **CCO (Chief Compliance Officer, 首席合规官)** 对 FDA 审计和数据完整性签字。
- **供应链 VP** 管采购, 库存, 寄售合约。
- **外科服务 VP** 管医生资质, 手术排班, 临床数据。
- **临床质量总监** 和 **医务总监** 负责不良事件监测与同行评议。

关键事实, 后面所有建模都从这里推导: **这套数据库的所有者是 MAOHN 这家医院, 不是器械制造商, 不是 GPO 集采组织, 不是 FDA, 也不是第三方 UDI 合规 SaaS。** 凡是出现 "成本", 都是医院方付出去的成本; 凡是出现 "召回响应", 都是医院方作为患者安全第一响应人要做的事。

## 2. 商业模式

像绝大多数美国医院集团一样, MAOHN 的营收按 "每次就诊 (per visit / per case)" 计算, 由各类付费方 (payer) 买单。骨科业务的付费方结构大致如下:

| 付费方 | 骨科营收占比 (典型) |
|---|---|
| Medicare 和 Medicare Advantage | 约 55% |
| 商业保险 (BCBS, UnitedHealthcare, Aetna, Cigna) | 约 30% |
| Medicaid | 约 10% |
| 自费和其他 | 约 5% |

这里有一个非医疗行业的人最容易搞反的点, 值得讲清楚: **对一台植入手术而言, 植入器械本身是成本项, 不是营收项。** Medicare 不会按 "你用了多贵的假体" 付钱, 而是按 DRG (Diagnosis Related Group, 诊断相关组) 打包支付。比如 MS-DRG 470 对应 "无并发症的主要关节置换", 这笔打包钱里已经包含了假体的钱。换句话说, 收入是固定的, 假体越贵, 医院利润越薄。

由此推出 MAOHN 的核心经济学: **每在器械采购上省下 1 美元, 几乎都直接落到利润上。** 在一次骨科住院的总成本里, 植入器械要占 40% 到 60%, 是单笔金额最大, 也最可压缩的一块。这就是为什么 **植入器械成本控制长期排在 CFO 的前三优先级**, 也是为什么这套数据库在合同定价 (contracted price) 和寄售 (consignment) 上做了如此细的建模。控制成本的前提是看得清成本, 而看清成本需要把 "哪个序列号, 在哪天, 按什么合同价买进来" 一路追到底。

## 3. 行业概览

骨科植入物是高度监管的医疗器械生意。从一个外行视角, 这个行业可以这样理解。

**这个行业创造什么价值。** 植入物厂商设计, 生产, 灭菌并分销那些要被永久或半永久放进人体的金属与高分子部件 (髋臼杯, 股骨柄, 膝关节假体, 脊柱钉棒, 接骨板螺钉等)。医院是买方和使用方, 负责把器械正确植入, 并在器械的整个体内寿命期里追踪它。一旦器械出问题 (断裂, 松动, 感染, 设计缺陷), 责任链会同时牵涉厂商和医院。

**主要玩家有哪几类。** 上游是器械制造商 (本数据集里以 Stryker, Zimmer Biomet, DePuy Synthes 等真实公司名做样本数据, 但 MAOHN 公司本身是虚构的)。中间常常有 GPO (Group Purchasing Organization, 集团采购组织), 帮医院谈批量折扣合同。下游是医院和外科医生。一个特殊之处在于, 骨科采购在很大程度上是 **医生驱动 (surgeon-driven)** 的: 外科医生对特定品牌的器械有强偏好 (业内叫 physician preference item), 这让医院在压价时谈判空间受限。

**谁来监管。** 美国市场的核心监管者是 **FDA (美国食品药品监督管理局)**。与本数据集直接相关的法规包括: 器械上市审批 (510(k), PMA, De Novo, HDE 等通路), UDI (Unique Device Identification, 唯一器械标识) 强制标识与 GUDID 数据库, 不良事件强制申报 (21 CFR Part 803, 即 MDR), 质量体系法规 (21 CFR Part 820), 以及电子记录与电子签名规范 (21 CFR Part 11)。加拿大市场对应的监管者是 **Health Canada**。本数据集默认北美市场, 货币为 USD。

**当前的宏观趋势。** 行业正在经历几股力量: UDI 合规从 "建议" 变成 "强制", 把追溯压力压到医院侧; 集采和医院集团整合把定价权往买方挪了一点; 关节置换正在从住院往门诊手术中心 (ASC) 迁移; 真实世界证据 (real-world evidence) 和器械登记系统 (registry) 越来越被监管和支付方看重。MAOHN 搭建这套登记系统, 正是踩在最后这股趋势上。

## 4. 项目背景与你的角色

你是 MAOHN 数据分析团队的一名分析师, 直接服务于上面提到的那几位高管和业务负责人。你手上这套 **骨科植入物中央登记系统 (orthopedic implant registry)** 不是医院的交易系统 (transactional system), 而是一个 **下游的分析数据集市 (analytical mart)**: 每晚由 5 个上游系统统一汇入, 专门用来回答跨系统, 跨医院的分析问题。

你的交付物通常是这几类:

- 给 CFO 和财务团队的 **成本看板** (各医院, 各年度的植入成本)。
- 给 CMO, CCO 和召回协调员的 **召回响应工作清单** (哪些患者体内有受影响器械, 通知发了没, 确认了没)。
- 给临床质量委员会的 **质量与结局报告** (不良事件率, 翻修率, FDA MDR 申报包)。
- 给供应链 VP 的 **库存与合同合规分析** (即将过期库存, 库存周转, 实付价是否符合合同)。

这套系统之所以要单独存在, 而不是直接在 Epic EHR 或 ERP 里查, 是因为下面四件事单靠任何一个上游系统都做不到, 它们正好定义了本项目的四大支柱:

1. **FDA Part 11 加 UDI 合规追溯。** 每一件已植入器械都必须从制造商批次 (lot) 一路追溯到具体患者, 并保留全量审计日志。这是 21 CFR Part 820 和 Part 803 的强制要求。
2. **SLA 范围内的召回响应。** 当 FDA 或厂商发布召回, MAOHN 必须在监管时间窗内把货架上受影响的库存拉走, 找到每一位体内已植入受影响单元的患者, 并完成通知。Class I 召回 3 天, Class II 30 天, Class III 60 天。错过会被罚, 还会引来诉讼。
3. **单例成本控制 (cost per case)。** 植入器械占骨科住院总成本的 40% 到 60%。供应链团队需要能下钻到 "每个序列号花了多少钱, 哪些是寄售, 哪些因过期或召回而浪费"。
4. **不良事件与远期临床结局监测。** 用于 FDA MDR 申报, 以及医院质量委员会的持续改进评审。

## 5. 要回答的业务问题

整套数据集是围绕下面五个业务问题设计的。每个问题都有对应的 SQL 查询去回答它 (具体编号见 `03` 号文档), 这里只讲问题本身。

**问题 1, 也是这个项目的招牌问题: 召回来了, 我们能不能在 SLA 内找到并通知每一位受影响的患者?** 召回分两种作用域: lot 级 (只召某一批 bad lot) 和全产品级 (整条产品线召回)。设计缺陷类召回往往是全产品级的, 一旦漏掉就是监管事故。我们需要随时能拉出 "当前所有活动召回牵涉的全部已植入患者", 标出谁还没通知, 谁通知了还没确认, 哪些已经超出 SLA。

**问题 2: 每家医院, 每年, 在植入器械上到底花了多少钱?** 这是 CFO 例行要的成本汇总。难点在于价格不是一个固定数字: 同一个产品在不同时间, 不同合同类型 (GPO, Direct, Consignment) 下成交价不同。正确口径是用每个单元 **收货当时 (point in time)** 生效的合同价, 而不是当前目录价。

**问题 3: 我们实付的价格, 是不是真符合合同?** 采购团队要审计 GPO 合同价的执行情况。如果某家厂商, 某种合同类型下的实际折扣常年低于行业基线, 那就是钱在悄悄漏出去, 需要重谈合同。

**问题 4: 哪些器械, 哪些医生, 临床结局更差?** 临床质量团队按统一口径监测不良事件率 (按手术算, 不按植入物算), 翻修率, 以及厂商和医生层面的离群值。这些数字进供应商记分卡和医生同行评议, 也是 FDA MDR 申报的依据。

**问题 5: 库存有没有在白白浪费, 周转健不健康?** 供应链要找出 90 天内即将过期的高价值库存, 找出周转率低, 资金占用高的医院, 还要确保最近一次质检失败的批次没有混进库存被用掉。

除了这五大问题, 数据集还支撑一批日常运营查询: 手术量的滚动 12 个月趋势, 医生手术量排名, 各术式的平均手术时长, FDA 各申报通路的批准率, 在审高价值产品的预判等等。这些不挂在某个高管的头号 KPI 上, 但天天有人在用。

## 6. 数据范围概览

这套数据集刻意做得比真实登记系统小, 方便教学。几个关键边界:

- **时间跨度。** 所有日期锚定在固定参考时点 `REFERENCE_DATE = 2026-06-01` (生成器里叫 `NOW`)。手术, 采购, 库存事件大致覆盖此前约 2 年; 制造批次和价格历史可回溯到此前约 5 到 6 年。把参考时点固定下来, 是为了让查询结果可复现, 不会因为今天是哪天而变化。
- **数据量。** 20 张表, 合计约 14,000 行。量级上是 "几百名患者, 上千台手术, 两三千个库存单元, 上万条事件日志" 的规模, 不是真实医院那种百万级。
- **范围裁剪。** 单一医院集团 (12 家医院), 单一专科 (骨科), 北美市场, 货币 USD。没有建模 HIPAA 同意书, 没有规范化的过敏和并发症表, 审计日志是示例性的而非完整事务级跟踪。这些裁剪是有意为之, 目的是让 SQL 模式清晰可见, 而不被合规样板内容淹没。具体取舍在 `02` 号 ER 文档的 "已知限制" 一节有完整交代。

需要强调的是, 数据虽然是合成的, 但分布是按真实行业惯例校准的: 召回等级里 Class II 占多数, 不良事件以 Minor 为主, 510(k) 批准率约九成, 高价值品类的寄售比例明显更高。这些刻意埋下的分布特征 (业务陷阱) 正是 SQL 查询要去暴露的东西。

## 7. 行业知识科普

这一节是外行读懂这套数据所需的那 30 到 60 分钟背景。已经熟悉的可以跳读。

### UDI: 器械的身份证

**UDI (Unique Device Identification, 唯一器械标识)** 是 FDA 强制的器械标识体系, 由两部分组成:

- **UDI-DI (Device Identifier, 器械标识)**: 标识 "这是哪个型号的产品", 同一型号所有器械共享同一个 DI。本数据集里用 GS1 的 GTIN-14 格式 (14 位数字, 带前导零)。
- **UDI-PI (Production Identifier, 生产标识)**: 标识 "这是该型号里的哪一件具体器械", 由批号 (lot), 序列号 (serial number), 有效期等拼成。

在条码里, 这些信息用 GS1 应用标识符 (Application Identifier, AI) 打头: `(01)` 后面跟 GTIN, `(10)` 后面跟 lot, `(21)` 后面跟序列号。本数据集的 `inventory.udi_pi` 就是按 `(01){UDI-DI}(10){lot}(21){serial}` 拼出来的。一句话: DI 告诉你 "是什么", PI 告诉你 "是哪一件"。召回要靠这套标识精确定位到批次和单件。

### 批次 (lot) 与序列号 (serial)

器械按 **批次 (lot / batch)** 生产, 一个批次几十到几百件。每一件物理单元再有自己唯一的 **序列号**。lot 级召回只波及某一批; 单件追溯则要落到序列号。MAOHN 的库存表 (`inventory`) 一行就是一个物理单元, 序列号全局唯一, 一旦植入就只能用一次。

### 寄售 (consignment) 与买断 (purchase)

骨科高价值植入物常走 **寄售模式**: 厂商把货放在医院货架上, 但所有权仍归厂商, 直到这件器械真正被用在某台手术上, 医院才结算付钱。约 60% 的高价值植入物 (髋, 膝, 脊柱, 肩) 是寄售。这有个重要的财务含义: 寄售库存不占医院的资金 (capital), 因为还没买; 所以算 "资金占用" 时, 寄售单元要被剔除。买断 (purchase) 则是医院先付钱买进来放着, 资金已经压在货架上。

### DRG 打包支付

**DRG (Diagnosis Related Group)** 是 Medicare 的打包付费机制: 按诊断分组定一个固定支付额, 不管医院实际花了多少。**MS-DRG** 是 Medicare 用的具体版本 (如 MS-DRG 470 = 无并发症的主要关节置换)。打包支付是 "假体是成本不是收入" 这个核心逻辑的制度根源。

### 召回 (recall) 的三个等级与 SLA

FDA 把器械召回按风险分三级, 每级有不同的响应时限 (本数据集采用的 SLA):

| 等级 | 风险含义 | 通知 SLA |
|---|---|---|
| Class I | 可能导致严重伤害或死亡 | 3 天 |
| Class II | 可能导致暂时性或可逆伤害 | 30 天 |
| Class III | 不太可能造成伤害 | 60 天 |

MAOHN 收到召回后, 要在对应天数内完成对患者, 医院, 医生的通知。本数据集把 "通知是否超 SLA" 建模为一个可被 SQL 直接算出来的指标。

### FDA 上市审批通路

一个器械要合法上市, 要走某条 FDA 审批通路:

- **510(k)**: 最常见, 证明与已上市器械 "实质等同", 周期较短 (典型 3 到 6 个月), 批准率高 (约九成)。
- **PMA (Premarket Approval)**: 最严格, 用于高风险器械, 要做临床试验, 周期长得多。
- **De Novo**: 给没有等同前例但风险又不高的新器械。
- **HDE (Humanitarian Device Exemption)**: 给罕见病器械的特殊豁免通路。

### 临床与运营里的几个标识和评分

- **NPI (National Provider Identifier)**: 美国医生的全国统一 10 位编号。
- **MRN (Medical Record Number)**: 病历号, 只在本院范围内唯一, 跨医院不通用。
- **ASA score**: 麻醉前评估病人整体身体状况的分级 (1 到 6, 数字越大越差)。
- **CPT 码**: 标识做了什么手术操作。**ICD-10 码**: 标识诊断是什么病。
- **创伤中心等级 (trauma level)**: I 级能处理最重的创伤, 逐级递减。

### 不良事件申报: MDR 与 MAUDE

当器械相关的不良事件发生 (感染, 松动, 断裂等), 医院可能要向 FDA 提交 **MDR (Medical Device Report, 医疗器械不良事件报告)**。这些报告汇入 FDA 的公开数据库 **MAUDE**。本数据集的 `adverse_event` 表就是 MDR 申报的素材来源。

### 数据分层: raw, silver, gold

这套数据集刻意做成三层, 方便你既练 "从原始事件查", 也练 "直接读派生好的当前态":

- **Raw (原始 / 铜层)**: append-only 的事件流, 是唯一可信源。比如 `inventory_movement` 记录每一次物理动作, `pricing_history` 记录每一次价格变更。
- **Silver (银层)**: 从 raw 派生出来的 "当前态" 缓存。比如 `inventory.status` 和 `inventory.location` 都是从最新一条 movement 倒推出来的。
- **Gold (金层)**: 预聚合的分析视图, 在 SQL 文档里以 `CREATE VIEW` 定义, 供看板直接用。

当 silver 与 raw 看起来不一致时, 永远以 raw 事件流为准。生成器是先建 raw 事件再派生 silver, 所以两层在结构上不会漂移。

### 价格历史的 SCD2 建模

价格随时间和合同变化, 用 **SCD2 (Slowly Changing Dimension Type 2, 缓慢变化维度第二型)** 建模: 每条价格记录带一个生效区间 (`effective_date` 到 `end_date`), `end_date IS NULL` 表示当前仍生效。要查 "某单元收货那天的价格", 就找包含那个日期的区间。

## 8. 术语表

下面把全数据集会用到的术语集中解释一遍。英文术语保留英文 (这是行业通用写法), 后面给一句大白话解释和一句 "在这里为什么重要"。

| 术语 | 大白话解释 | 在这里为什么重要 |
|---|---|---|
| **UDI** | 唯一器械标识, FDA 强制的器械 "身份证" 体系 | 召回和追溯的基础 |
| **UDI-DI** | 标识 "是哪个型号产品" 的部分 | 全产品召回按它定位 |
| **UDI-PI** | 标识 "是哪一件具体器械" 的部分 (含批号, 序列号) | 单件追溯靠它 |
| **GUDID** | FDA 的全球 UDI 数据库 | 产品和厂商参考数据的源头 |
| **GS1 / GTIN / AI** | 全球通用的条码标准; GTIN 是 14 位商品编号; AI 是条码里 `(01)(10)(21)` 这种段前缀 | `udi_pi` 字段的拼装规则 |
| **lot (批次)** | 一次生产出来的一批器械 | lot 级召回的作用域 |
| **serial number (序列号)** | 单件器械的唯一编号 | 每件只能植入一次 |
| **consignment (寄售)** | 货放医院但所有权归厂商, 用了才结算 | 寄售库存不计入资金占用 |
| **purchase (买断)** | 医院先付钱买进来 | 资金已压在货架上 |
| **GPO** | 集团采购组织, 帮医院谈批量折扣 | 合同价合规审计的对象 |
| **DRG / MS-DRG** | Medicare 的打包付费分组 | 假体是成本不是收入的制度根源 |
| **payer (付费方)** | 为就诊买单的一方 (Medicare, 商保等) | 决定营收结构 |
| **510(k) / PMA / De Novo / HDE** | FDA 的四条器械上市审批通路 | `regulatory_submission` 的 `submission_type` |
| **recall class (召回等级)** | FDA 按风险把召回分 I / II / III 级 | 决定通知 SLA 是 3 / 30 / 60 天 |
| **SLA** | 服务水平协议, 这里指规定的响应时限 | 召回响应是否达标 |
| **MDR** | 向 FDA 提交的器械不良事件报告 | `adverse_event` 的归宿 |
| **MAUDE** | FDA 收录 MDR 的公开数据库 | 质量评审包的对照源 |
| **NPI** | 美国医生全国统一 10 位编号 | `surgeon.npi_number` |
| **MRN** | 病历号, 本院内唯一 | `patient.mrn` |
| **ASA score** | 麻醉前身体状况分级 (1 到 6) | 反映患者基础风险 |
| **CPT 码** | 标识做了什么手术操作 | `surgery.procedure_code` |
| **ICD-10 码** | 标识诊断是什么病 | `surgery.diagnosis_code` |
| **trauma level (创伤中心等级)** | 医院处理重大创伤的能力分级 | `hospital.trauma_level` |
| **revision (翻修)** | 对原植入手术的二次返工手术 | 翻修率是核心结局指标 |
| **point in time price (时点价格)** | 某单元收货当时生效的合同价 | 成本核算的正确口径 |
| **SCD2** | 带生效区间的价格历史建模法 | `pricing_history` 的结构 |
| **raw / silver / gold** | 原始事件层 / 当前态层 / 预聚合视图层 | 整套数据的分层逻辑 |
| **EHR** | 电子病历系统 (本集里是 Epic) | 临床数据的上游 |
| **ERP** | 企业资源计划系统 (本集里是 Workday) | 采购与库存的上游 |
| **SIS** | 手术信息系统 | 手术植入事件的上游 |
| **21 CFR Part 11 / 803 / 820** | FDA 关于电子记录 / 不良事件申报 / 质量体系的法规编号 | 这套系统的合规依据 |

## 9. 关键指标与公式

下面这些指标会在 SQL 查询里反复出现。这里给出统一口径和公式, 避免不同查询算出互相打架的数。当一个指标有两种常见算法时, 本数据集明确选定一种并贯穿全文。

**不良事件率 (adverse event rate)。** 统一口径是 **每 100 台手术** 的事件数, 不是每 100 件植入物。一台用了多枚植入物的手术里出现 1 起事件, 应该算 1 台受影响的手术, 而不是 N 件。

```
不良事件率 = 有事件的手术数 / 手术总数 * 100
```

**召回响应 SLA 达标。** 用 "从召回发布到发出通知的天数" 对照该召回等级的 SLA 天数。

```
days_to_notify = notification_date - recall_date
超 SLA = days_to_notify > sla_days   (Class I = 3, Class II = 30, Class III = 60)
```

**时点合同价 (point in time price)。** 一个单元的成本, 取它收货当时生效的那条价格记录。

```
unit_cost = pricing_history.contracted_price_usd
其中  effective_date <= inventory.received_date
 且   (end_date IS NULL OR end_date > inventory.received_date)
```

**单例植入成本 (cost per case)。** 先把一台手术用到的所有植入物的时点成本加起来, 再在医院或年度层面汇总。注意要先在手术层聚合, 否则一对多 join 会把 "平均每台手术植入物数" 算虚高。

```
cost_per_surgery = SUM(该手术每个单元的 unit_cost)
```

**库存周转率 (inventory turnover)。** 已用单元占该医院全部库存单元的比例。

```
turnover = Used 单元数 / 全部库存单元数 * 100
```

**资金占用 (capital tied up)。** 只算买断的, 仍可用的库存。寄售单元要剔除, 因为还没买。

```
capital_tied_up = SUM(contracted_price_usd  WHERE status = 'Available' AND NOT is_consignment)
```

**2 年翻修率 (2-year revision rate)。** 骨科结局学的核心指标。分母是每位患者的首次 (非翻修) 植入手术 (index case), 分子是其中在 730 天内发生了翻修的数量。

```
revision_rate = 730 天内翻修的 index case 数 / index case 总数 * 100
```

**FDA 批准率 (approval rate)。** `Withdrawn` (主动撤回) 不计入分母, 因为撤回不等于被拒。

```
approval_rate = Approved 数 / (Approved + Pending + Denied) 数 * 100
```

**合同折扣率 (discount rate)。** 实付价相对目录价 (MSRP) 的折扣幅度。

```
discount_pct = (list_price_usd - contracted_price_usd) / list_price_usd * 100
```

**批次质检状态 (lot QC status)。** 一个批次算 "通过质检", 当且仅当它最近一条定论性结果 (`Pass` 或 `Fail`, `Conditional` 不算定论) 是 `Pass`。这个状态是查询时算出来的, 不存成固定布尔字段。
