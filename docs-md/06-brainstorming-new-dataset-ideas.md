# 索引建好之后, 怎么想下一个 dataset 的点子

[05-dataset-index.md](05-dataset-index.md) 讲的是把每个精修好的 dataset 浓缩成一行摘要, 汇总进 [dataset/INDEX-cn.md](../dataset/INDEX-cn.md) 和 `dataset/INDEX.md` 这份清单, 让人一页扫下来就知道仓库里有什么. 这份清单一旦建好, 它就不只是一个查阅工具了, 它还是一张覆盖地图: 哪些行业已经有了, 哪些 use case 反复出现, 哪些格子还空着, 全都摆在一页里. 这篇要讲的就是怎么把这张地图利用起来, 用 [.claude/skills/brainstorm-dataset-ideas](../.claude/skills/brainstorm-dataset-ideas/SKILL.md) 这个 Skill 去想下一个 dataset 该做什么, 让仓库的行业和用例覆盖越来越多样, 而不是在几个熟悉的方向上反复打转.

---

## 1. 想点子这一步, 排在索引之后是有道理的

从零起草 (`fake-data-generator`), 审查打磨 (`review_and_fix_loop.py`), 到索引汇总 (`update-dataset-index`), 前面几步解决的都是 "把一个已经定下来的 dataset 做扎实" 这件事. 但在动手做之前, 总得先有一个值得做的点子, 而好点子不是拍脑袋来的. 一个人闷头想, 很容易一直往自己熟悉的行业和用例上靠, 结果仓库里堆了五个营销归因数据集, 却没有一个物流或者能源的.

把想点子这一步排在索引之后, 就是因为索引清单正好提供了想点子最需要的那个输入: 一张现有覆盖的全景图. 有了这张图, 才谈得上有意识地避开已经做过的, 去补真正缺的那块. 所以这个 Skill 干活的第一件事, 永远是先读 [dataset/INDEX-cn.md](../dataset/INDEX-cn.md), 把现有 dataset 按行业和 use case 两个维度在脑子里摊开, 再在这个基础上想新的.

---

## 2. 两种想点子的模式

这个 Skill 支持两种截然不同的想法来源, 靠调用时传不传参数来区分.

第一种是**按现有分布补空白**. 不带参数直接调用, Skill 就照着覆盖地图找洞: 哪些行业还完全没碰过 (比如 hospitality, 航空物流, 能源, 教育, 游戏), 哪些 use case 模式在现有行业里很薄, 或者哪个老行业还没和某个用例组合过. 然后一次给出五到八个尽量互不重复, 尽量分散在不同格子里的点子, 目标就是把覆盖面往外推.

第二种是**由岗位描述反推**. 用户丢给它一段 Job Description, 连带背后的 Industry, Company, Role, 意思是: 这个岗位上的人每天做的那些 project, 背后需要一份什么样的数据和 use case 才能撑得起来? Skill 会先把这个岗位每天到底在做什么想清楚, 再倒推回去: 这个人天天在看, 在查, 在喂给模型的是什么数据? 那份数据就是 dataset, 那个反复要做的决策就是 use case. 这一模式一次给一到三个贴着岗位的点子, 而且每个点子都会写清楚 "岗位映射", 也就是数据的哪一部分对应岗位上的哪一项日常工作.

不管哪种模式, Skill 都会拿新点子跟现有清单对一遍, 如果发现某个方向其实已经有 dataset 覆盖得挺好了, 它会照实说出来, 然后把点子往还没被覆盖的角度上挪, 而不是造一个近似的重复品.

---

## 3. 这个 Skill 只想点子, 不动手做

需要特别强调的一条边界是: 这个 Skill 从头到尾只负责想, 不负责做. 它不会在 `dataset/` 下建任何东西, 不写生成脚本, 不碰真实数据. 它唯一的产出, 是把想出来的点子用中文固定写进 `tmp/idea.md` 这一个文件里, 写完就停.

`tmp/idea.md` 里每个点子都按同一套模板展开: 建议的数据集名字 (照着 `{行业}_{用例}_{规模}` 的命名惯例), 行业, 虚构的北美公司画像, 目标使用角色, 核心 use case 和业务问题, 数据故事, 核心实体和表的粗略构想, 建议规模和量级, 内嵌业务陷阱的想法, 以及和现有 dataset 的差异点在哪. 由岗位反推的那些点子还会多一条岗位映射. 这样一份点子清单足够具体, 具体到可以直接作为下一步的输入, 但它本身还只是个想法, 做不做, 做哪个, 决定权仍然在人手里.

---

## 4. 点子清单怎么接回到生产流程

`tmp/idea.md` 是这条流水线里一个刻意做轻的交接点. 想点子和做 dataset 之间隔着一次人工挑选: 人扫一遍这份点子清单, 挑中其中一个觉得值得做的, 再把它的业务背景用自己的话描述给 `fake-data-generator`, 由那个 Skill 起草初稿. 从这里开始, 流程就重新回到 [01-dataset-anatomy.md](01-dataset-anatomy.md) 到 [05-dataset-index.md](05-dataset-index.md) 讲过的那条老路: 起草, 打磨, 审查, 最后重新跑一遍 `update-dataset-index` 把新 dataset 加进索引.

于是整件事就转了一整圈, 变成一个可以持续下去的循环: 索引反映出仓库当前的覆盖, 想点子的 Skill 读着索引找出下一个该补的空白, 补完之后又更新回索引. 每转一圈, 仓库覆盖的行业和用例就多样一分, 而不是靠运气或者个人偏好来决定下一个 dataset 是什么.
